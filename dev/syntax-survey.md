# The syntax survey and the ideation record

The record of one pass over Baker's language: what the text form is today, what binds any change
to it, where it pinches, and every change proposed and judged before eight were prototyped on
branches (`dev/syntax-ideas.md` compares the prototypes). Made with a workflow of subagents:
seven readers mapped one area each, a critic ranked what they found, eight ideators proposed
radical changes from one angle each, three judges scored every proposal under one lens each,
and a synthesizer merged the overlapping ones into briefs. Numbers were measured over the 68
`.dta` files in `tests/`, `examples/` and `stacks/` at commit `565bb63`. Nothing here is a
decision; the decisions are the owner's, listed at the end of `dev/syntax-ideas.md`.

## The seven areas

### The lexer, the parser and the printer

Baker's text form is a Lisp-like s-expression language with no formal grammar file; the grammar is the hand-written Lexer and Parser in /home/user/baker-dev/src/data/parse.cpp (1,433 lines) plus the shared lexical predicates in src/data/text.hpp/.cpp, and D10 records the details the spec left open. The lexer is a byte scanner: every byte <= 0x20 is whitespace, ';' comments to end of line, '/*...*/' comments only where a token would start, and an atom runs until one of the bytes in the 256-entry kAtomEnd table (control/space, the six brackets, '"', ';'; text.hpp:41-49, D199). An atom is then classified in a second pass (D202): '#name' is a directive (a lone '#' is the symbol '#', D101), '$name' a Var, classify_number decides Int (decimal or 0x hex, signed, int64 range; hex denotes its unsigned value) or Float (fast_float general format, finite doubles only; 'inf'/'nan' are symbols), an out-of-range number is a Range error, and anything else is a Symbol (text.cpp:48-99, parse.cpp:239-279). Strings are '"..."' with exactly two escapes, '\n' and '\q', every other backslash literal; quoted symbols are "'...'" with no escapes; both may span lines and end at the first closing quote (parse.cpp:188-237). Three bracket pairs make three array-like node kinds: '(...)' Array, '{...}' Command, '[...]' Property, except that '[' at a file's top level defines a macro and '(' after '#define NAME' on the same line is a macro body, and '{' after '#autorun' is collected into the session (parse.cpp:535-609, 875-907; D11). A file's first form '(pack ...)' or '(origin "..." ...)' is consumed as a declaration (parse.cpp:598-607). The parser builds nodes on one flat scratch Vec<Node> with a frame stack and makes each array in the load's arena on close (D64), splicing macro bodies by sharing arrays, bounded by ParseLimits (depth 256, include depth 32, 4,096 files, 2^26 nodes; parse.hpp:68-73). Every array keeps file, line, height and flags in a 24-byte header followed by a run of 4-byte tag keys and then 16-byte Nodes (array.hpp:621-628, D77, D29); a Node is an 8-byte union plus a 1-byte Type with 7 reserved padding bytes (node.hpp:324-335), and the binary cache stores both as a memory image with static_asserts on the offsets (cache.cpp:22-38, kVersion 6). The printer (write.cpp) is the inverse of the lexer in the structural sense only: it writes each node in a canonical spelling (shortest round-trip floats with a forced '.0', decimal ints even for hex input, symbols bare iff is_bare_symbol else single-quoted, strings with the two escapes), a compact one-line form or a pretty form that breaks an array when it exceeds width-indent columns, and drops comments, directives, macros and formatting; D13 lists the values it cannot spell and D226 makes number text identical across platforms via a to_chars-equivalent fallback. Text preservation lives elsewhere: an edit-mode parse records byte spans per node (SourceMap) and write-back edits exactly those bytes (config_write.cpp:303, 279-284). read_structure (D220) runs the same Lexer in a tolerant mode and returns tokens, brackets (parent, tag, closed) and comments with byte spans plus the errors, for editors; it is the one place comments are exposed. Throughput is measured by bench/bench_parse.cpp (4.2 MB generated config text, best of 10, Release: 209-213 MB/s and 43 allocations after D199, from 115 MB/s at M1), by tools/count (200 parses of 16 KB under cachegrind: 1,845,499 instructions per parse after D220) driven by tools/count_instructions.py and tools/bench_compare.py (worktree of the base commit, alternating runs, medians and ranges). The lexer is about 40% of a parse (D199/D202: lex_token 13.2%, lex_atom 8.6%, classify_number 5.8%, fast_float 3.9%), and the one-pass lexer was measured to a ceiling under the 10% bar and not built. The real-corpus gate (D101) holds the grammar to 464/464 raw Harmonix files and lists exactly which converted files fail and why. The core is at 15,190 of its 15,500-line soft budget (tools/count_lines.py), which bounds how much grammar can be added.

Where it pinches:

- **medium.** `[` means two things by position and a Property can never be top-level; real converted data with a top-level `[1 0]` fails, and a spliced macro holding a Property at top level is an error (parse.cpp:539-540, 499-502; D11; D101 (42 Amplitude files); test_preprocessor.cpp:79-80)
- **medium.** `#` is three things: directive prefix, the bare symbol `#`, and the `#remove` marker symbol that is a directive in one slot and a quoted symbol everywhere else; any other bare `#x` is a hard 'unknown directive' error (parse.cpp:243-247, 842-849; write.cpp:21-36; D101 (59 files), D143; tests/fuzz_regressions/README.md (quoted_remove_symbol.bin); test_write.cpp:57 ('#if' must be quoted))
- **medium.** Quoted symbols have no escape, so a symbol that needs quoting and contains `'` cannot be written or printed; strings cannot hold `\n`/`\q` literally; Var names with delimiters and Func nodes are also unprintable but D13 does not list them; Path names with `'` cannot be printed either (D13; text.cpp:101-115; write.cpp:66-70; test_write.cpp:120-140 (the random test scrubs these cases); fuzz/lookup_harness.cpp:66-71 (skips names with quotes))
- **medium.** Number/symbol ambiguity is asymmetric: a malformed number (`1e`, `1.2.3`, `0xZZ`) is a symbol but an overflowing one (`99999999999999999999`, `1e309`) is a fatal Range error, so 78 converted locale files with a 20-digit bare name fail; and any atom that reads as a number must be quoted to be a symbol (`'12'`, `'1e5'`, `'-1'`) (text.cpp:48-99; parse.cpp:266-273; D101; test_write.cpp:53-55; test_parse.cpp:69-76, 91-93)
- **medium.** The printer loses spelling: hex prints as decimal (`0xFF` -> `255`), so round-tripping a flags or color file through write_file or promote rewrites it; float widening prints `0.1f` as `0.10000000149011612` unless the caller goes through float_to_decimal_double (write.cpp:41-45; test_write.cpp:44-46; D10 ('hex is how flags and colors are written'))
- **medium.** No comment- or layout-preserving printer: write_dta drops comments, directives, macros, pack/origin forms and indentation, and its default indent (2) differs from the house style (3) in README, docs and corpus; a formatter has nothing to build on but read_structure's spans and write-back's hand-made render_entry (write.hpp:5-7; write.cpp:99-122; README.md default.dta (3 spaces); config_write.cpp:64-74, 279-284; D220)
- **low.** The grammar exists only as code: no grammar file, the lexer and classify_number are the specification (D10 'details the spec leaves open'), and the token kinds are declared twice (Tok and TextTokenKind); read_structure's agreement with the parser is held only by the corpus test (parse.cpp:19 vs parse.hpp:212-223; test_structure.cpp:94-108; D10)
- **low.** Two passes per atom (scan to the delimiter, then classify_number rescans) and about ten instructions per whitespace byte; the lexer is ~40% of a parse and the one-pass rewrite's ceiling (9.6%) is under the 10% bar so it was not built (D199, D202; text.cpp:48-99; parse.cpp:121-162, 239-279)
- **low.** Strings have only two escapes (`\n`, `\q`): no tab, no `\\`, no unicode escapes, no raw or multi-line delimited form; a literal newline inside quotes is the only multi-line spelling, and the first `"` always ends the string (parse.cpp:188-219; D10; D101 (17 RB4 files with unescaped quotes fail))
- **low.** `/*` opens a comment only at a token start, so `a/*b` is one symbol but a symbol starting with `/*` must be quoted; a reader cannot tell from the bytes alone (parse.cpp:139; text.cpp:106; test_write.cpp:58-59; D10)
- **low.** The same-line rule for `#define NAME (body)` is the only layout-sensitive rule in an otherwise free-form grammar, and the language doc's directive table omits it (parse.cpp:881; D11; docs/language.md directive table ('#define N (body)' row); test_preprocessor.cpp:87)
- **low.** First-form declarations are recognized by tag and position, so ordinary data tagged `pack` as a file's first array is silently consumed; `origin` was guarded by requiring a string value, `pack` was not (parse.cpp:598-607; D91; test_parse.cpp:258-259 (a pack error has no column))
- **low.** Spec and docs disagree with the code in several lexical details: spec §1 says Int/Float are 32-bit (D18 widened), `#include "path"` quoted (bare accepted, D11), `(pack name (layer L))` (code: `level`, D80), Var is 'pointer to a variable slot' (code: the name Symbol), Object is `Object*` (code: 64-bit handle, D19); docs/language.md's Nodes table says Property is 'a property of $this, in a method' while the parser accepts `[...]` as Property anywhere below top level (dev/spec.md §1 Node types and Directives; docs/language.md Nodes table; node.hpp:5-15; parse.cpp:539-540)
- **low.** Whitespace is every byte <= 0x20 but DEL and invalid UTF-8 are symbol content, and line endings are counted by `\n` only; columns count code points by a continuation-byte test, so a file with mixed encodings reports columns that an editor may not agree with (parse.cpp:131-134, 98-108; test_parse.cpp:131, 236-237; D169)
- **low.** No boolean literal: TRUE/FALSE are user macros, and the parse benchmark's `(enabled TRUE)` is a bare symbol unless defined, so bool fields read as 'symbol, not bool' errors in data that forgot the macro file (docs/language.md:48-50; bench/bench_parse.cpp text; D85)

### The preprocessor, macros, packs and layers

The preprocessor is the parser: one recursive-descent pass (src/data/parse.cpp, class detail::Parser, 387-987) lexes `#name` atoms as Tok::Directive (parse.cpp:243-247; a lone `#` is the symbol `#`, D101) and dispatches them in `directive()` (851-909); nothing a directive does ever lands in the tree, so merge, lookup, the cache and every tool see only expanded data. State that crosses files lives in a LoadSession (include/baker/parse.hpp:114-200, LoadSession::State at parse.cpp:312-383): one HashMap `defines` holds both flags (`#define N`, null body) and macros (`#define N (body)`, top-level `[N ...]`), plus include dirs, the reader, `autorun` commands, the `#require`d-path set, pack levels, packs, origins, macro `definitions` (D178), the macro-to-pack attribution, warnings, and the record a cache needs (D72/D73). A macro is a named sequence of nodes spliced wherever its name appears as a bare, unquoted symbol, tag position included (parse.cpp:519-533; tests/data/test_preprocessor.cpp:57-64); expansion shares the macro's arrays by reference rather than copying, which write-back, `check`'s repeat report and the cache all rely on. Files declare themselves packs or generated by a positional first form, `(pack name (level L) ...)` or `(origin "src" (tool t))`, which the parser records in the session and drops from the tree (parse.cpp:599-606, 676-753; D82, D91). Packs carry a level ranked by `set_pack_levels`, `requires` (by pack name, with optional versions, D141/D147), and harness metadata; the one-way rule warns, once per file and macro, when a harder pack's file expands a softer pack's macro (parse.cpp:764-781, D80/D82). Removal is the reserved symbol `#remove`, accepted only as a tagged array's single value and stored in the tree with an Array-header flag (parse.cpp:837-849, src/data/array.cpp:65-88, D143). Meaning is then given by one merge routine with two policies (src/data/merge.cpp:111-260): within a tagged array the *values* are every node after the tag that is not a tagged array and the *children* are the tagged arrays; Overwrite (Config layers) replaces the whole value list and recurses into children by tag, FillMissing (`#merge`) keeps existing values and only adds missing keys (D1, D15, D31); duplicate tags match the first occurrence, `''` is no tag (D125), untagged arrays are values, rebuilt arrays are shared when identical to the incoming one (D127), an index kicks in past 32 incoming keys (D75), and `(key #remove)` is applied after the loop, only under Overwrite, and stripped from any subtree a layer adds. A Config reads each file layer with a copy of the session left by the layer below (`session_below`, config_impl.hpp:321-323; config.cpp:168-236), so macros, defines and `#require` flow upward through the stack and never downward; that is why reload re-parses from the lowest changed layer up (D35), why placing a layer below others or removing one re-reads everything above (config.cpp:562-631, D144), and why a title update cannot change a macro the base already expanded (dev/background/content-updates.md:81-82). `read_session()` is the top file layer's session, refreshed per merge, and is where packs, origins and macro definitions reach tools (D110). Provenance never lives in the text: `source()` asks the layers' own trees top-down for the first enabled tree with values at the path (`supplier`, config_impl.hpp:435-445, D32) and takes that array's file and line plus the origin its session recorded; `explain` (config_write.cpp:590-680, D154), `layer_effect` and `diff` walk the same trees. Write-back needs an edit-mode SourceMap with a byte span per node and the `macro` symbol that marks a spliced node (include/baker/source_map.hpp), and refuses values from macros, overlays, text layers, `#merge`-assembled arrays without spans, and changed files (config_write.cpp:150-215). The binary cache records what a load began with (macro bodies by hash, pack levels, required paths) and every effect it had on the session, and replays them (src/data/cache.cpp:74-85, 617-690); shipping compares the beginning in memory (D139). Received text (`push_layer_text`) reads the same way but with `refuse_includes` and `text_only` (D163, D142), and `LayerPolicy` classifies syntax forms (commands, `#autorun`, `#remove`) for refusal (D161). In the real data of this repository the directives are rare: six `#require`s (all the stacks' pack files), three `#include`s, one `#merge`, one `#define` file, one `#ifdef` pair, three `#autorun`s, eleven `(pack ...)` and two `(origin ...)`, and no `#remove` outside tests, while the external DTA corpus gate (D101: 464 of 464 raw Harmonix files parse and round-trip) is the stated compatibility bar.

Where it pinches:

- **high.** Macros are untyped, unscoped, global in read order, and expand at every bare symbol including tag position and inside later macro bodies, so any macro name collides with any key or value symbol in every later file and layer; quoting is the only escape and flags and macros share one table so `#ifdef` sees both. (test_preprocessor.cpp:60-63 ((TAG 1)[TAG t](TAG 2) → (t 2)), :99; D10; parse.cpp:519-533)
- **high.** A title update or higher layer cannot change a macro's effect in the layers below it, because each layer expanded the macro when it was read; the cookbook can only advise 'change values, not the macros below you'. (dev/background/content-updates.md:69 (scenario 4), :81-82, :190; docs/cookbook.md:484-486; config.cpp:168-266)
- **high.** No way in a layer to append to, remove one element of, or address by position a value list: Overwrite replaces the list and repeated tags are matched first-to-first, so the convention 'everything packages extend must be a keyed table' is unenforced and only layer_effect reveals a replaced list. (D31 ('an override that must reach the third phase needs keyed phases'); content-updates.md scenarios 2 and 5; cookbook:468-481; D142 'no new syntax or check')
- **medium.** Two spellings for one macro, with a whitespace-sensitive rule: `[kMax 4]` versus `#define kMax (4)` (the body must open on the same line or the define silently becomes a flag and the array becomes data); scalars must be wrapped in parentheses in the #define form. (parse.cpp:881; tests/corpus/macros.dta:3-11 uses both; test_preprocessor.cpp:84-88; D11)
- **medium.** Write-back refuses any value a macro supplied ('edit the macro's definition instead') and any array #merge assembled without spans; a designer tuning a shared colour or kDefaultVolume in the harness cannot save it. (config_write.cpp:195-204; test_config.cpp:667-677; spec §1 lines 174-177; D34)
- **medium.** `#remove` is a value-position marker with a special-cased symbol: it prints bare only in one slot and quoted elsewhere (a fuzzer found the round-trip bug), promote cannot write it, scalars_only/existing_only must name it, and it needs a header flag; it cannot remove a list element or an unkeyed entry. (D143 'fuzzer finding'; write.cpp:21-36; config_write.cpp:457-461; config_check.cpp:223-238; content-updates.md scenario 5)
- **medium.** Pack and origin declarations look like data and are recognised by position and a String-typed first value; `(origin 0 0 0)` had to be carved out, a second origin or a later (pack ...) silently becomes data, and the reserved child vocabulary (level, requires, version, owners, for, stage, tool) is checked only there. (D91 'a settlement of the spec's as a top-level form'; parse.cpp:599-606; test_preprocessor.cpp:533-541, 557-559)
- **medium.** A dependency is written twice in different currencies: `(requires combat_core)` by pack name and `#require "combat_core.dta"` by path, checked at different times (requires after the file is read; require at the directive) and matched differently (name vs normalized candidate path). (docs/cookbook.md:544-545; parse.cpp:938-960 vs 1142-1163; D81, D141)
- **medium.** `#autorun {command}` is the only way data defines script, one command per directive, with `{` required immediately; the commands are invisible to the merged tree (check missed calls until D158, Config::autorun was empty until D107), and a multi-line class definition rides behind a directive meant for one-liners. (D107, D158; stacks/hearth/data/default.dta:78-100; parse.cpp:898-907; config_check.cpp:174-181)
- **medium.** Conditionals are token-level and may unbalance brackets across branches, so no tool (read_structure, formatter, editor outline) can see or fold a conditional, and a Directive token followed by a Symbol is all an editor gets. (test_preprocessor.cpp:107; parse.cpp:1342-1431 (no cond tracking); test_structure.cpp:25-40)
- **medium.** Tools cannot tell a macro use from a symbol without a load: read_structure marks Macro only for `[name ...]` in the same text, never for `#define` macros or cross-file ones; the editor needed macro_definitions (D178) because text scanning for `#define`, `[` and `{func` 'misses anything a macro makes'. (parse.cpp:1349-1351, 1409-1414; test_structure.cpp:85-91; D178 preamble)
- **medium.** Macro flow forces whole-stack re-reads: placing a layer below others or removing one re-parses every layer above, and shipping pays ~50 ns per macro per layer to verify caches began alike. (D144 'Re-reading'; D35; D139 cost table (8.6 → 18.3 µs with 200 macros); config.cpp:562-631)
- **medium.** `[` is overloaded (top-level macro definition vs property), so a Property can never be top-level, a spliced property at the top is an error, and 42 Amplitude corpus files with `[1 0]` fail. (D11; parse.cpp:499-502, 539-541; D101)
- **medium.** A .dta file has no notion of its layer: layer names, order, optionality and placement live only in C++ or the project file, and a test or an overlay author must push files to build a stack; provenance names a layer only because the Config kept the trees apart. (D32; project.hpp:1-45; config.hpp:5-10; test_received_layers.cpp:37-54)
- **low.** `#merge` has the opposite direction to layers (fill-missing, app-over-defaults) and lives in the same language as Overwrite layering; the slide discrepancy needed a code comment and a D-entry, and the directive is used once in the repository. (D1; merge.cpp:108-110; tests/corpus/config_app.dta:12 (only use); test_preprocessor.cpp:224-247)
- **low.** The `#` namespace is split by length: a lone `#` is a symbol but `#1`, `#00aa00` and `#$%&` fail as unknown directives (59 corpus files), and the printer must quote every `#`-led symbol. (D101; parse.cpp:243-247; text.cpp:101-108)
- **low.** Versions cannot be written as numbers: `(version 1.10)` is refused because the float lexer reads 1.1, so the pack syntax carries a 'write it as a string' error. (D147; parse.cpp:642-674; test_preprocessor.cpp:406-414)
- **low.** `source()` of a container is ambiguous ('the topmost enabled layer that has it') and explain refuses containers, so the questions tools ask about sections rather than leaves have no answer. (config.cpp:753-761; config_write.cpp:676-679; D154 'A path that names arrays of arrays is refused')
- **low.** Shared macro arrays make sort_for_lookup and any in-place change visible through every expansion, and height limits bite on long macro chains. (array.hpp:525-531 ('every array sharing this one (through a macro) sees the change'); test_preprocessor.cpp:289-295)

### Script

Baker's script is the same s-expression text as its data, with three "code" node kinds: a Command `{f args...}` or `{object method args...}`, a Var `$name`, and a Property `[name]`/`[a b]`; there are exactly ten node types (include/baker/node.hpp:44-55) and the evaluator, `check`, the cache, the printer and the data-only layer policy all key on those three (src/script/reference.cpp:16-18, src/data/config_check.cpp:105-107). Evaluation is lazy and has no special forms: `Context::Impl::call_body` resolves the head (a Symbol is looked up in a flat per-Context function table indexed by `Symbol::index()`, else in the named-object table; an Object node, or a Command/Var head evaluated to an Object, dispatches as a method; a Property head is refused) and hands the raw command to a thunk; nothing evaluates an argument until the native reads it by type through `Args::get<T>(i)`/`read_into`, whose fast path converts a literal in place and whose slow path evaluates a Command/Var in the same Context and converts the result (src/script/context.cpp:237-303, include/baker/script.hpp:1023-1075). Natives are bound by signature deduction: each parameter type P selects a `detail::Param<P>` with a kind (Value, Raw, Optional, Rest, Implicit), a `match` predicate and a type name; `Raw<Node>` is passed as written, `Raw<Var>` is "a place" (a `$var` cell or a `[prop]` array), `std::optional<T>` a trailing optional, `Args` the rest, `Context&` and a method's `Self<T>` take no argument, and anything else goes through `Convert<T>` (script.hpp:371-468, object.hpp:200-216). A name registered twice with another signature becomes an overload set, which evaluates every argument once into eight stack slots (spilling to the default allocator) and takes the first overload that fits exactly, then with Int promoted to Float; a function with a Raw parameter cannot be overloaded, and an identical signature is refused at registration (context.cpp:337-388, 593-629). Variables are dynamically scoped by shallow binding: `$name` is a Symbol whose index addresses one cell per Context in pages of 1,024, an unset cell is an error, `{do ($a ($b 1)) body...}` and every script function/handler call save and restore cells through `Rebind` even on error, and a callee sees and may clobber its caller's variables (D44, D47, internal.hpp:272-276, 365-381). `{func name ($p...) [(status s [repl])] [(doc "...")] body...}` and `{override ...}` define script functions whose body is the definition array from an index on (no copy, the load's arena stays alive), with one untyped "value" parameter per `$p`, so `check` can only count their arguments (builtins.cpp:30-95, reference.cpp:212-216). `{class T (method ($p...) body...) ...}` attaches handlers to a bound C++ type or declares a script-only class, `{extend T ...}` adds or replaces single handlers, `{new C [name] (param value)...}` creates and `{delete obj}` removes (deferred to the host's outermost eval or the tick's sync point, D117/D67); dispatch is script handler (most derived first, gated by one `handled_names` bit), then native method overloads, then the universal `get`/`set`/`type`/`name` (object.cpp:286-344). In a handler `$this` is an ordinary dynamically bound variable named `this`, `[k]` reads a bound property or loose parameter of it and `[a b]` walks on into objects or tagged arrays, and `{set [k] v}` stores one (object.cpp:368-392, 560-577). Typed messages give a C++ aggregate a script face: `b.on<HitMsg>` binds a method named `M::name` with M's fields as parameters so `{bob hit 20}` and `bob.handle(HitMsg{20})` converge, the C++ path costing ~9 ns and no Node (object.hpp:345-372, 458-470, D66). Tasks are methods of a Scheduler object (`scheduler` by default; Hearth names a second one `clock`): `{scheduler delay_task t body...}`, `{scheduler interp_task $var from to body...}`, `{scheduler thread_task cmd...}` with `{wait cond}`, `{wait_for t}`, `{wait_tick}` recognized only as a thread's own top-level commands by head symbol and arity; each task is a pooled coroutine that captures by value, when made, up to 16 bound variables its body names and ends with its `$this` object (script_tasks.cpp). A command in data means "a value computed when it is read": `find_int`, `get<T>` and every typed lookup try the raw values first and, only if that fails and a value is a Command or Var, evaluate those values (not arrays nested in them) in the calling thread's current Context (innermost `Context::Scope`, else the evaluating Context, else the first created on the thread) and convert again; raw reads (`find`, `at`, `find<Node>`) never evaluate, and without a Context the lookup fails cleanly (D45, context.cpp:106-112). `check` walks trees without evaluating and reports arity errors against every overload and literal-argument type mismatches, skipping any argument that is a command, variable or property and any raw or rest parameter; it collects `{func}`/`{override}` arities, `{class}`/`{extend}` handler names and `{new Class name}` objects first so cross-file calls count as defined, produces the demand report (unresolved heads, stubs, unknown methods "on" a class), the one-way warnings, repeats, owner findings and, for a Config, tweak findings, as text and as versioned JSON `baker.check/1.3` (reference.cpp:20-325). `Context::declare`, `declare_type` and `declare_object` let a tool rebuild the game's vocabulary from the reference JSON (`baker.reference/1.2`): a parameter is a type name from a fixed table of Baker's names (value, unevaluated, values..., $variable, array, symbol, string, name, bool, int*, uint*, float*), a host type a native of the same Context takes, or a described list of value types; a declared function refuses to run unless given a body (D175, D176, D211, D213, context.cpp:631-928). The reference (Markdown and JSON) is generated from the Context, `docs/script-reference.md` is regenerated by the tests and fails on drift, and `eval_request` answers `(ID {command})` lines with one JSON reply. A native call `{add 1 2}` costs about 31 ns with zero allocations (README, D78, D124, D211), a script function 77–85 ns, a native method 62–84 ns, a C++-to-script call 113 ns, a task step 66–76 ns, and every one of these is pinned by allocation-counting tests because `baker_alloc_tests` fails if a Context reaches `operator new`. The core is 15,080 of its 15,500-line soft budget (D224), `baker::script` about 4,000 of it. Where the docs and code disagree: spec §5 still describes a Var as a pointer to a slot and a handler cache in the node (D44 replaced both with symbol-indexed tables), 32-bit numbers (D18: 64), three tiers including macro (code has Native and Script only, D47), `Object*`/`T*` parameter types (the code reaches objects through `Node` and `ctx.try_get<T>`, and `Self<T>` is implicit for methods only), and `check` opt-in via a Config flag (it is a free function plus `check_validator`); `Type::Func` exists in code only as the unset-variable sentinel (internal.hpp:166-169), not the spec's "bound native function"; and the generated reference lists `wait`/`wait_for`/`wait_tick` as `values...` functions though their real forms are fixed-arity pseudo-commands a `thread_task` pattern-matches (script_tasks.cpp:91-100, 232-243).

Where it pinches:

- **high.** Conditions are nested prefix braces with no infix, no range, no cond/else-if: every metric in the stacks writes `{and {>= $value lo} {<= $value hi}}`, and clamp is two nested ifs. (stacks/ledger/metrics/ledger.dta:8,12,16,20,40; stacks/duel/metrics/duel.dta:22,31,36,51,56,61; stacks/stuntline/metrics/track.dta:11 `{and {> $value 0} {<= $value {* 1.5 {track.par}}}}`; examples/calculator/functions.dta:5 `{func clamp ($x $lo $hi) {if {< $x $lo} $lo {if {> $x $hi} $hi $x}}}`; examples/scripting/rules.dta:7)
- **high.** No iteration in the vocabulary: no while/for/foreach, no list words; recursion is the only loop and is capped at 1,000 calls or 256 KB; the DTA-derived corpus already writes `{while ...}`, which check reports as demand and the test stubs by arity. (tests/corpus/ui_menu.dta:30-36 `{do ($i) {set $i 0} {while {< $i kMaxPlayers} {player_join $i} {set $i {+ $i 1}}}}`; tests/script/test_check.cpp:145-160; tests/script/test_eval.cpp:156-164; docs/script-reference.md (25 functions in all))
- **high.** Script function parameters carry no types or docs, so check only counts arguments to them and the reference shows `{<Goblin> hit $n}`; hosts that wanted checkable signatures had to get them from C++ (`declare`), not from data. (src/script/builtins.cpp:79-82; src/script/reference.cpp:212-216, 596-602; tests/script/test_object.cpp:354-355; D175, D213 (requirement notes 0003, 0012))

### Shapes and metadata

Baker's type system is two systems bolted to the same untyped tree. The first is baker::shape (include/baker/shape.hpp, src/shape/shape.cpp, 540 lines of a 600-line budget): a record schema declared in data inside one top-level container, (shapes (name (at path...) (keyed) (field type meta...) ...)), where every shape and every field is an array tagged by its own name so that Config's merge-by-tag stacks declarations across layers (D84 replaced spec section 6's top-level (shape name ...) form for exactly that reason). A shape governs every array tagged with its name anywhere, narrowed by (at ...) to arrays whose tagged ancestors from the root match the listed segments (`*` matches one), or, declared (keyed), every child of the arrays at that path whatever its tag (D108) - which is how all 24 shapes in the six stacks are written, because keyed tables are the content convention that layers merge by name (D142). Field types are int, float, bool, symbol, string, any, (list T) or another shape's name; metadata is (range lo hi), (step s), (kind k), (desc "..."), (note "..."), (optional) and (one_of ...), and any other tag is silently ignored. check() walks the tree once (by tag, by keyed path, and into fields of shape type, each nested array checked once, D119), reporting wrong type, arity, range, one_of and missing required fields as located errors with a path, and undeclared fields as warnings; commands, variables and properties are skipped. shape::validator() runs any-thread over a ValidatorStack after every merge and in layer checks (D166), reading each layer's own tree bottom to top with the session's packs so that a softer pack may narrow a harder pack's field but not loosen it (D145); the load never fails on a shape, and the host copies findings into CheckReport::shape_errors/shape_warnings for the check gate. The second system is Tweak<T>: a C++ constant that registers a path and optional TweakMeta (range, step, desc, kind, group, dev_only, one_of, choices), binds to the merged tree, and takes its metadata from the data file when the data has it: trailing arrays tagged range, step, desc, note, kind, group or one_of after the value are metadata and the value stops before them (D88, D218); note is data-only; group defaults to the path's parent; a given kind wins, else 3 or 4 numbers ranged exactly 0..1 present as "color" (D37, tweak.cpp:235-241). check_tweaks (D206) holds a merged tree to the registered tweaks (type, range, one_of, choices, missing paths, stray keys beside a group) and DescribedTweaks lets a tool rebuild the registry from the reference JSON (D210, D212, D215). Three JSON documents expose it all to tools: baker.shapes/1.1 (shape::write_json), baker.tweaks/1.3 and baker.check/1.3, sorted and byte-stable, with fields added only in minor versions. Metadata is ordinary data throughout: scalars read the first value and ignore the rest, so (width 2 (range 0 10)) reads as 2; paths reach it (box.width.note); layers restating a value keep the range below; write-back replaces the untagged values and keeps the metadata. The pinches follow from that: the seven metadata keys collide with ordinary vocabulary (kind, desc, step are field names in the stacks and only the trailing-run rule disambiguates); shapes sit in a separate pack file and must restate the data's path to reach it, so a wrong depth governs nothing silently; there is no reuse (identical field sets are declared twice), no tuple, map, command or default type (22 of 121 stack fields are `any` with the real type in desc prose; component names live in desc), and the same range and desc are written in C++ TweakMeta and again in the data for 47 tweaks, with the texts already drifting. The project file (include/baker/project.hpp, src/data/project.cpp) is a fixed-key form, (project (pack_levels ...) (include_dirs ...) (defines ...) (reference "...") (tool "..." args) (console N) (scenarios ...) (objectives ...) (step_name x) (layers (name "path" [optional] [disabled] [dev_only]) ...)), read text-only with includes refused and unknown keys as located errors; it names no schema, so tools reach the shapes only through the game's reference JSON.

Where it pinches:

(stacks/contraption/data/default.dta:26-28, 57 (`(ball (kind ball) (pos -6 6.5))`), stacks/stuntline/data/default.dta:14-23 (`(kind straight)` as a piece's first field), stacks/ledger/data/default.dta:25-29 and stacks/hearth/data/default.dta:47 (`(desc "...")` as a record field), stacks/wayfarer/data/default.dta:16 (a tweak named `step`), shape fields named kind/desc in stacks/stuntline/packs/game/stuntline_core.dta:7, contraption_core.dta:14; the rule itself: src/data/tweak.cpp:31-43, D88, D218 ('(ball (kind ball) (pos 1 2)) is all value'))

### The tooling that depends on the text

Everything in this area treats a .dta file as bytes with a side table, not as a tree. An edit-mode parse (LoadSession::source_map, on by default outside shipping) records each file's whole text and, per array, its extent (brackets included) and one contiguous byte span [begin,end) per child node, marked with a macro name when the node was spliced from a macro (include/baker/source_map.hpp:25-32; src/data/parse.cpp:487-533, 583-587; D33, D128). Comments, whitespace and directives are never stored: they are "the text between spans", so write-back works by replacing token spans in place and keeping every other byte, which is what makes the diff one line (src/data/config_write.cpp:288-332; tests/data/test_config.cpp:633-656). Config::write_back walks the supplying layer's own tree by Path, refuses with a located ErrorCode::Refused whenever any step is not a literal token in one file (macro, #merge-rebuilt array without spans, overlay/tree layer, text layer, non-edit-mode layer, a file whose bytes changed since the read, values spread over files, an index the layer lacks), and otherwise replaces only the untagged children (the "values"; tagged trailing arrays are metadata, D88) with the printer's compact spelling, keeping an integer token's form for a whole float (D183) and writing numbers identically on every platform (D226). write_back_to inserts a missing entry as the last child of the deepest ancestor written in that file, after the previous sibling's line, re-indented with that sibling's leading whitespace, in the pretty-printer's form (config_write.cpp:243-286); a missing optional file is created from scratch. promote plans every leaf of a layer (duplicates folded as merge folds them, D134) against a virtual re-read of the target, all or nothing, refuses (key #remove) leaves (D143), and the host kit's promote --patch captures the writer to emit a line-level unified diff (src/host/commands.cpp:276-345, 366-413). The printer (include/baker/write.hpp, src/data/write.cpp) is the other half of the text contract: parse(print(tree)) is structurally equal, the quoting rule is one function shared with the lexer (src/data/text.cpp:101-108), floats get ".0" to stay floats, #remove prints bare only in its marker slot, and values the text cannot spell (nan/inf, a symbol needing quotes that holds a quote, a string with a literal \n or \q) print lossily (D13). read_structure (D220) runs the parser's own lexer tolerantly and gives tokens, brackets (parent, tag = first symbol token, closed) and comments with byte spans plus the problems, for editors; it expands no macros and marks only top-level [NAME ...] macros. The project file baker-project.dta is a closed (project ...) grammar read through the same edit-mode map so every entry carries a 1-based line and code-point column (src/data/project.cpp:16-55, 100-213; D172, D173, D204, D208, D212, D217, D223). The console is line-framed Baker text: a line whose first non-blank is '(' is a request (ID {command}) answered by one baker.reply/1.1 JSON line, anything else is ctx.eval(line, "<console>") answered "=> value" or describe(error), every reply followed by an empty line (src/host/console.cpp:56-95; src/script/request.cpp:119-158); the reply's "text" is the printer's compact form and is the authority, "value" is a lossy projection keyed on the tag-as-first-node convention. The config.* script functions take paths and layer names as symbols or strings and return data that projects to JSON (src/script/config_tools.cpp). The host kit's commands (check, reference, eval, diff, promote, sim, compare) read argv with a "{...} is a command" rule, open the stack through Live without watching, and write versioned JSON (baker.check/1.3, baker.sim/1.2, baker.compare/1); scenarios and objectives are (scenario NAME ...)/(objective NAME ...) forms read by tag and index, and sim writes results.dta, a second DTA record that compare reads back. The binary cache stores the expanded tree (format version 6, source order, nothing absolute) plus a meta tree of the load's files, defines, macros, #autorun, packs, origins and definitions; edit mode and cache_dir are exclusive, so write-back and caches never meet in one Config (src/data/cache.cpp:40-101; src/data/config.cpp:186-210; D73, D74, D148). Live, Watcher and loop_stats depend on the text only through content hashes of every file the session reader served and through file:line provenance (D180, D221). The ImGui harness reads TweakRegistry metadata, cfg.source() for hover, the "(note ...)" metadata through a path, shapes from root(), and drives set/write_back/write_back_to("local")/clear_scratch/promote. Budgets are tight: the core is at 15,080 of 15,500 lines and the host kit at 2,360 of 2,400 (tools/count_lines.py:13,87; D223).

Where it pinches:

- **high.** Write-back cannot touch a value that comes from a macro, which is the corpus's idiom for named constants ((master_volume kDefaultVolume)); it refuses with "edit the macro's definition instead", and no API edits a macro definition either, so the live edit stays unsaved. (src/data/config_write.cpp:200-205; tests/data/test_config.cpp:667-677 and 860 ("kDefaultVolume and kMaxPlayers are macros", the corpus gate expects at least two refusals); dev/spec.md:174-177)
- **medium.** A removal cannot be promoted: (key #remove) is a key's only value, so writing it beside the key's children in the target would not parse; promote refuses and asks for a hand edit. The same spelling keeps write-back from ever expressing "delete this key". (src/data/config_write.cpp:457-462; D143 ("promote refuses a removal leaf"))
- **medium.** Insertions are blind to directives: write_back_to adds a new entry after the last child's line, and the source map records no #ifdef/#else/#endif spans, so when the last child sits inside a conditional branch the new key lands inside that branch (inferred from the code; no test covers a conditional target). (src/data/config_write.cpp:257-285 (position from the last child's span and the array's extent only); include/baker/source_map.hpp:3-14 (directives are not recorded); docs/language.md:150-162 (the #ifdef-inside-an-array idiom))
- **medium.** The projection is lossy by design (symbol vs string, (a (b 1)) vs (b 1), repeated tags fall back to arrays), so a tool that needs exactness must parse the "text" field, which is DTA: the promise that a tool "never parses Baker text unless it wants to" holds only for simple values. (docs/reply-json.md:36-37, 65-66; src/script/request.cpp:39-50, 66-90; tests/script/test_request.cpp:51-55 (repeated tags become [["a",1],["a",2]]))
- **medium.** One syntax, two readings: a repeated tag is folded by merge (later values win) and promote writes that, but layer_effect, diff and find() take the first child; a tool's diff and the file it promotes can disagree. (D134 ("Left as they are. layer_effect and diff still list each tag's first child"); src/data/config_write.cpp:42-53 vs 93-110)
- **medium.** A non-finite float writes back as the bare word inf or nan, which re-reads as a symbol: write-back silently changes the value's type on the next load. (tests/data/test_config.cpp:1114-1117 ("(weird inf)" is the expected file text); include/baker/write.hpp:13 (D13: nan/inf read back as symbols); src/data/config_write.cpp:137-139 keeps the float)
- **medium.** read_structure marks only [NAME ...] definitions as macros, not #define NAME (body), and reports tokens in inactive #ifdef branches like any other, so an editor's highlighting and go-to-definition diverge from the parser's view (which treats both macro forms alike). ### The language as it is written

The written corpus is 66 .dta files and 1,449 lines (1,214 non-blank non-comment, 157 comment-only, 74 lines with a trailing `;` comment): 46 files and 1,037 lines under stacks/ (7 games: data, packs/game, metrics, sim, baker-project), 14 small example files, 7 test-corpus files in the Harmonix style, and 5 host-test files. Measured with a tokenizer that honours strings and comments, it holds 2,516 open brackets for 5,167 atoms (0.49 brackets per atom), of which 65.6% are symbols, 27.9% numbers and 6.5% strings; 19.5% of all atoms sit inside metadata arrays (`range`, `desc`, `step`, `kind`, `note`, `optional`, `one_of`), which are 17.5% of all arrays. Nesting reaches 6 deep (hearth residents' weights, a mission objective's goal command, a scripted `{wait {$this arrived}}` inside a class handler, songs.dta's track lists) and is typically 3 to 5; an agent overriding one Duel move value writes 5 nested parentheses. Tagged arrays break down into 1,028 single-scalar settings `(tag value)`, 328 multi-scalar vectors `(size 0.8 1.8 0.7)`, 550 records holding only child arrays, 99 values with trailing metadata, plus 66 untagged tuples such as `(0 -5 14 0.2)`. Four idioms carry nearly all the content: the tuning row with inline metadata (51 rows, 47 of them `(name value (range lo hi) (desc "..."))`, 7 with `(step)`), the keyed table whose child tags are the keys (136 records under keyed parents in the stacks' data, governed by 22 `(keyed)` shapes declaring 133 fields), the positional vector whose layout lives in prose, and the command-as-value (174 tagged arrays hold a `{command}` in data: goals, unlocks, milestones, measures). Script in data is thin: 7 `{func}`, 2 `{class}`, 1 `{new}`, 0 `{extend}`, 3 `#autorun` (one of them Hearth's 31-line `#autorun {class villager ...}`), 345 braces in all, 161 `$variables` of which 71 are the objectives' `$value` and 34 `$this`. Harness files are formulaic: 27 scenarios and 54 objectives (8 `(over median)`), where 15 passes are the band `{and {>= $value A} {<= $value B}}`, 13 are `{== $value 0}` and 8 `{== $value 1}`, 12 scenarios say `(seconds 0.02)` because an analysis still needs a length, and 7 Duel scenarios differ only in two symbols each. Nine project files exist, 7 of them identical but for the console port; 11 `(pack ...)` declarations, 2 `(origin ...)`, 9 `#require`, 3 `#include`, 1 `#merge`, 3 `#define`, 6 `[MACRO ...]`, 1 `#ifdef`/`#ifndef` pair, and 0 `#remove`; every macro and conditional lives in tests/corpus only, none in the stacks or examples. Metadata is duplicated across the boundary: the 47 described tuning rows restate the `range` and `desc` that the games' 47 C++ `Tweak` declarations already carry (cube/main.cpp:18-27 against cube/data/default.dta:5-15), with the data's wording winning (cookbook, "Tweaks in practice"), while keyed records take their metadata from shapes in a separate pack file. Implementation-wise the text form is the Harmonix DTA grammar (spec §1, D10, D11, D101: 464 of 464 raw Harmonix files parse), with Baker's additions: `#require`, `#autorun`, `(pack ...)`, `(origin ...)`, `(shapes ...)` with `(at ...)`, `(keyed)`, `(list T)`, `(one_of ...)`, `(key #remove)`, the scenario and objective forms read by src/host/scenarios.cpp, and the project form read by src/data/project.cpp; the reserved words of each sub-grammar are plain symbols (tweak.cpp:20, shape.cpp:16-18), so `desc`, `kind`, `at` and `objectives` are simultaneously metadata keys, shape words, scenario words and ordinary data fields in the same corpus. A designer writing a row must know: the tag is the first symbol, values follow, metadata trails as tagged arrays with exact key names, booleans are `0`/`1` or a bare `(landmark)` or a `TRUE` macro, a mistyped number (`1_000`, `1e`) is silently a symbol, quoting is needed for spaces and punctuation, the child tag of a keyed table is what a layer merges by, positional order comes from a `desc` string or a `;` comment, `{}` makes a value script, and a second `{class}` replaces every handler. The stacks-agent loop (SKILL.md:41-59) is: read `reference`, metrics and sim; `sim --seeds 1-10 --results runs/before`; write `data/agent.dta` restating the full nesting path from the root with a `;` comment saying why; `check` (exit 0 or fix); `sim` after and `compare`; report with `diff`'s `player.speed  3.5 -> 4.5`; stop, and a person applies `promote --patch`, a unified diff that replaces one token per value and keeps the line's comment (`-   (speed 3.5)   ; how fast`). The audit (stacks/audit.md) rates the data files low in viscosity and close in mapping but names hidden dependencies (`{class}` after `{extend}` drops it; objectives live apart from the data), found no demand in the data because every stack was built with its vocabulary in hand, and found the repeated helpers in C++ instead (`truthy(node)` three times because every goal-as-command decides truth itself). The docs and code agree on the forms; the only drift found is that docs/language.md:122 writes `#define N (body)` without D11's same-line rule, and game-stacks.md §4 shows pre-D108 shapes the stacks no longer use.

### The spec's goals and the non-negotiables

Baker is an MIT C++20 library built from one public talk (Malafeew, GDC 2005) as a reimplementation "in the spirit of" Harmonix's DataArray; the spec (dev/spec.md:21-29) makes one goal non-negotiable: replacing a hardcoded constant with a configured, hot-reloadable, designer-editable value must cost one line and no ceremony, and everything else, including the text form, serves that plus the scripting layer that grows out of it. The text form is s-expressions with four bracket kinds: `(tag values...)` data, `{f args}` lazily evaluated commands, `[name]` properties (and, only at a file's top level, macro definitions), and `$var`; plus `;` and `/* */` comments, `'quoted symbols'`, `"strings"` with exactly two escapes, hex ints, and a `#` preprocessor (docs/language.md:33-133, D10, D11). Six goals bear on the syntax directly: the one-line tweak with metadata written beside the value in the file (spec:353-395, D88); designer-editability through a self-describing, schema-optional, forgiving format (halo-tags-vs-dataarray.md:81-89, spec:202-210); errors located by file, line, column and a path that pastes back (spec:148-158, D27, D169); write-back of a live-tuned value as a one-token diff with comments intact (spec:160-200, D33, D34, D183, D226); provenance for every value including the tool a generated file came from (spec:347-351, D91, D154); and the harness/agent loop in which `eval`, `check`, the generated reference, `#autorun`, packs and the project file let a console, an editor or an agent read, check and grow the data without the game (harness-tree-vision.md:417-430, D107, D172, D178, D220). The hard constraints are enforced by code, not prose: `static_assert(sizeof(Node) == 16)` (include/baker/node.hpp:334) and a 24-byte Array header (include/baker/array.hpp:638); no exceptions anywhere and `Expected<T>` on every fallible call (D54); public headers that reach only D55's standard headers, checked by tools/check_headers.py; allocation-free lookups, calls, messages and tweak reads proven by alloc_counter tests and `baker_alloc_tests` (spec:1001-1015, CLAUDE.md Gates); a parse throughput floor of 40 MB/s that the parser beats by 3-5x (README:167, D199) with instruction counts now the unit of argument (D169, D201, D202, D220); and a soft core budget of 15,500 non-test lines of which 15,190 are used today (tools/count_lines.py: data 10,055, script 5,135; shape 547/600; host 2,361/2,400), raised four times (D2, D40, D48, D69, D220) and never enforced, only reported. Legally the output must stay cleanly MIT: no code from the rb3/dc3 decompilations (spec:51-64), no Harmonix files in the repository or CI (D3), no DTB compatibility (spec:37, D104), and nothing borrowed in expression from any integration target (INTEGRATIONS.md rules 3-5, D151). What must keep parsing is three-tiered: tests/corpus (8 hand-written DTA-style files that must parse, round-trip structurally and survive every prefix truncation, and that seed the fuzzer), the 4 fuzz regressions plus a clean 10M-exec libFuzzer run (spec:1031-1032, D17), and the external gate run locally and recorded in D101 (464 of 464 raw Harmonix DTA files parse and round-trip; 30,684 of 30,979 community-converted files, where every failure is the conversion's and the parser stays strict rather than guess). DTA heritage is kept where real files depend on it (`#merge` fills missing keys, D1; `TRUE`/`FALSE` are macros, D85; a lone `#` is a symbol, D101; `#include_opt` and `#autorun`, D11; case-sensitive symbols for round-trip, D23) and dropped where the research showed it was accident (32-bit numbers became 64-bit and hex became unsigned, D18; Karaoke Revolution's `#macros.dta` include spelling is refused, D101). The modding-community expectation is informal rather than promised: the spec's provenance paragraph names Rock Band's config files as "the seam the modding community works through" (spec:10-15) and the cookbook teaches Rock Band's keyed `songs.dta` as the composition convention (docs/cookbook.md:466-477), but the README never claims DTA compatibility, and the raw-corpus gate is a recorded result, not a CI test. The Acton review (.claude/skills/gamedev-td/SKILL.md) is the posture every change meets: name the transform and its cost, pay nothing you do not use, decide at bake what the bake can decide (SKILL.md:111-115, 338-341; D105 contrasts DTB keeping `#ifdef` as nodes with `.datb` storing the expanded tree), treat "different data" as a different problem (SKILL.md:105-107; spec Appendix A:1128-1129 says script and data combine rather than subsume), keep strings off hot paths (names are Symbols, D6), and prove every claim with a bench row or a cachegrind count on the same machine; the lexer is 40% of a parse (D199), a per-token offset was rejected at 5.3% (D169), `#remove` was accepted at +1.1% only after a +4.0% version was redone (D143), and a lexer rewrite had to promise 10% to be tried (D201, D202). The cost of a second parser is already measured pain: D220 records that "each tool wrote its own lexer, a second copy of Baker's syntax that no test held to it", so the parser's own lexer now serves tools, and any syntax change lands in at least five places (the lexer, the tolerant `read_structure`, the printer that must spell every node, the edit-mode span table write-back splices through, and the external tree-sitter/LSP grammars). The spec deliberately leaves out a general-purpose language (no modules, no stdlib), a debugger, a serialization framework, static typing or a compile step, native vector types, comment-embedded metadata, epoch-cached pure commands, drop-in layers, a list-append marker and DTB (spec:31-37, 926-927; seexpr-vs-baker.md:233-245; D8, D104, D138, D142, D201), and it insists dynamic scoping and lazy evaluation stay as they are (spec:627-656, 809-811). Where the documents strain against the syntax, the pattern is consistent: a flat top level merged by tag forces declarations into positional first-form rules (`(pack ...)`, `(origin ...)` only as a first form with a string first value, `(shape ...)` moved into a `(shapes ...)` container: D82, D84, D91); metadata and values share one list so only tweaks, by a reserved-key list, can tell them apart (D88); keyed children and tagged instances are two spellings of the same thing that shapes and merge treat differently (D85, D108, D142); removal is a pseudo-directive stored as a symbol with special printing rules (D143); numbers that fail to lex fall back to symbols (D10) so real data depends on it and typos pass silently; and the scripting half is, by the sources' own words, wordier than data and hostile to artists (spec:1128, seexpr-vs-baker.md:102-115), which sits uneasily under a harness vision that wants gardeners writing L3 in data.

Where it pinches:

- **high.** Top-level declarations have no syntax of their own: `(pack ...)` is a declaration only as a file's first form, `(origin ...)` only first (or after pack) and only when its first value is a string because real data writes `(origin 0 0 0)`, and the spec's `(shape name ...)` had to move into a `(shapes ...)` container because Config merges top-level forms by tag. Positional and type-sniffing rules stand in for a declaration form. (D82 (dev/decisions.md:2285-2290), D91 (2535-2541), D84 (2329-2344); spec:118-132 vs docs/language.md:177-193, 233-247)
- **high.** Metadata and values share one list. A tweak's value ends before the first array tagged range/step/desc/note/kind/group, but a plain `get<T>` cannot tell metadata from an element, so `get<std::array<float,3>>` of `(tint 0.9 0.5 0.2 (range 0 1))` still fails; a value's own tagged children collide with the reserved keys by name. (D88 (dev/decisions.md:2442-2449); docs/cookbook.md:40-45; D218 split_metadata exists because the rule is a convention)
- **high.** Every tool re-implements the syntax: the editor integration wrote its own lexer before D220 gave it the parser's, the tree-sitter grammar and LSP live outside this repository, and the printer, write-back splicer, cache and fuzz dictionary each encode the token set again. (D220 (7143-7144); D153 (4662-4664); fuzz/dta.dict; D13)
- **medium.** Keyed children versus tagged instances are two spellings of one idea with different behavior: shapes match by tag so `(bosses (dragon ...))` needs `(keyed)`; merge composes keyed children but replaces value lists; `(boss (name dragon) ...)` is governed by name but repeated tags do not merge one by one. The convention is documented rather than expressed. (D85 (2375-2378), D108, D142 (4248-4252); docs/language.md:273-284; docs/cookbook.md:466-477; content-updates.md findings 4)
- **medium.** Removal is a pseudo-directive: `#remove` is lexed as a directive, accepted only as a tagged array's single value, stored as a reserved symbol, printed bare only in that position and quoted elsewhere (a fuzzer found the mismatch), and `promote` refuses a removal leaf because the text form beside children would not parse. (D143 (dev/decisions.md:4268-4274, 4292-4294, 4311-4314); docs/language.md:96-107)
- **medium.** Atoms that fail to lex as numbers silently become symbols (`1e`, `0xZZ`, `1.2.3`, `12abc`, `1_000`), so a typo in a number is a type error later, not a parse error; real converted data depends on the fallback (bare symbols that read as 20-digit integers or start with `#`), and tests/corpus pins it. (D10 (dev/decisions.md:140); D101 (2896-2901); tests/corpus/odd_tokens.dta:9)
- **medium.** Square brackets mean two things: a top-level `[NAME ...]` defines a macro, anywhere deeper `[...]` is a Property; consequently a Property can never be printed at a root's top level and splicing one there is an error. `#define NAME (body)` is a macro only if `(` is on the same line as the name, a whitespace-sensitive rule in an otherwise whitespace-free grammar. (D11 (dev/decisions.md:151-156); D13 (179); docs/language.md:41, 126)
- **medium.** Macros splice at read time and share arrays, so write-back refuses any macro-sourced value, a title update cannot change a macro the base already expanded, and quoted symbols are the only way to write a symbol that collides with a macro name. (spec:170-179; D34 (520-524); D10 (133-134); docs/cookbook.md:480-483; content-updates.md scenario 4)
- **medium.** Script is wordier than data and hostile to artists; the original's scripts were written mostly by programmers, yet the harness vision wants gardeners writing L3 vocabulary in data, and the single notation from L1 to L4 is claimed to remove the cliffs between layers. (spec:1128-1129, 1216-1217; seexpr-vs-baker.md:102-115; harness-tree-vision.md:276-289, 336-341; reading-a-studio.md:120)
- **low.** No boolean literal: `bool` reads any integer, `TRUE`/`FALSE` are macros each project must define, and a shape's `bool` field accepts numbers only. (docs/language.md:44-46; D85 (2373-2374); tests/corpus/macros.dta:3-4)
- **low.** `#ifdef` conditionals are token-level and may span brackets, so the text is not a tree until the preprocessor runs; the cache stores one expanded tree per define set, and the tolerant reader cannot show the structure of both branches. (D11 (157-158); D105 (2996-2998); D220 (7152-7153))
- **low.** Keys that are not bare symbols need `'quoted symbols'`, strings never key, and symbols are case-sensitive; the library compensates with error-path hints (suggest the quoted spelling, suggest a case variant) and a `check` warning for mixed case, which is evidence the syntax invites the mistake. (D6 (dev/decisions.md:94-97); D23 (313-316); spec:81-86 corrected menu example)
- **low.** Paths have two spellings (`.` in calls, `/` in error output) and an all-digit segment is always an index, so an index and a numeric-looking key are not distinguishable in a path. (D27 (dev/decisions.md:390-398); docs/language.md:57-63)
- **low.** Errors located by an array's line carry no column (lookups, shapes, script calls, pack and origin declarations); editors widen them from edit-mode spans themselves, because tracking a per-token offset in gameplay parses cost 5.3%. (D169 (dev/decisions.md:5396-5402); docs/language.md:480-481)
- **low.** A lone `#` is a symbol the parser accepts bare but the writer quotes (`'#'`), and any other unknown `#name` is an error; `#` is thus a directive sigil, a symbol and, in `#remove`, a value marker. (D101 (2884-2887); D143 (4269-4274); docs/language.md:132-133)
- **low.** Data files are forgiving (extra fields warn, missing paths default) but the project file is strict (an unknown key is a located error), so one grammar carries two validation philosophies chosen per form. (D172 (5513-5515) against spec:946-950 and docs/language.md:290-292)

#### Angle: expressions

EXPRESSIONS: script that reads like mathematics. Every proposal below is a parse-time rewrite to the head-first `{head args...}` array the runtime already reads, so the lexer's token set, the lazy evaluator (no special forms, tests/script/test_eval.cpp:88-102), check, the ten node kinds and the 16-byte Node, the cache (kVersion 6), D222's digest, the console's `(ID {command})` grammar and write-back's one-token spans are untouched: constraint 9's only route, and what keeps the 31 ns call and the 15,500-line budget (15,190 used, 310 free) intact. Evidence base, measured over the 68 .dta files (1,485 lines): 345 brace commands, of which 117 are operator calls, every one binary (33 `>=`, 23 `==`, 21 `<=`, 5 `<`, 3 `>`, 10 `+`, 3 `*`, 1 `/`, 16 `and`, 1 `or`, 1 `not`); 16 are the band `{and {>= $value A} {<= $value B}}`, 4 are `{if c a b}`, 3 are `{set $x {op $x ...}}`; 34 of the 161 `$` uses are `{$this ...}` heads, all in Hearth's class; 0 commands have a punctuation-only symbol at slot 1, 0 have `and`/`or` there, 0 heads start with `.`, 0 variables contain `.`, and `$"` is a parse error today. So each rewrite is a strict extension in this repository; the D101 gate (464/464 raw Harmonix files, run by hand in 41 s) must be re-run counting rule firings, because a firing would be a silent change of meaning, not a parse error, which is the one thing the owner refused in D101. Considered from this angle and declined: lexical `let` (spec section 5 and script.hpp:18-22 forbid lexical scoping, D44 rests the one-load variable read on shallow binding, and no reader-side rewrite gives lexical capture, so a `let` that desugars to `do` would lie about scope); pipelines `{$v |> clamp 0 1 |> round}` (no site in the corpus chains transforms; the reader would synthesize nested calls for no measured consumer; `->` is Ledger's recipe symbol in data); `obj.method(args)` call parentheses (adjacency-sensitive `name(` breaks DTA's layout-free grammar and any raw file written `(tag(x))`); `=` as an alias of `set` (a C programmer's `{$a = 1}` in a condition would assign); booleans (a literal, the literals angle's). Recommended order: curly-infix first, self-dot-methods beside it, expr-precedence only if curly-infix's corpus rewrite shows people nesting mixed-operator braces, str-interpolation last because no site needs it today.

**`curly-infix`.** Inside `{...}` only, a brace whose odd slots hold one and the same unquoted punctuation operator is an infix chain the parser rewrites head-first when the brace closes (`{0.3 <= $value <= 0.7}` is the tree `{<= 0.3 $value 0.7}`), and `{c ? a : b}` is the one two-operator form (`{if c a b}`). Mixed operators are a located parse error ('nest braces'), not a precedence table: sweet-expressions' curly-infix discipline. No lexer change, no evaluator change, nothing new in the tree, so laziness, check, the cache, the digest and the console are untouched; the operators become variadic and `+= -= *= /=` join the vocabulary. It is the right radical move because it buys a designer's spelling for 76 of the corpus's 213 top-level commands at the price of one rule a reader learns and a handful of instructions per command close.

*Objection, and the proposer's answer:* Acton school and DTA heritage: 'A second spelling of the same tree is a transform; the uniform `{head args}` is why there are no special forms and why every tool reads a command the same way; sweet-expressions spent fifteen years failing to catch on in Lisp; the printer now says something other than what the file said; and the D101 owner refused lenient rules precisely because a silent reinterpretation is worse than an error.' Honest answer: the transform runs once at parse, on commands only, for a handful of instructions per close that count_instructions must show inside noise; the tree stays uniform, so the runtime, check, cache, digest and every JSON document see exactly what they see today, and the only thing the runtime gains is variadic operators it should have had. The printer does not lie, it canonicalizes, as it already does for hex (`0x1F` prints `31`, D18) and whole floats; the cost is that promote writes prefix, bounded by one flag bit if the owner wants spelling kept. The D101 point is the serious one: a raw Harmonix brace with a punctuation-only symbol at slot 1 would change meaning without an error, so the gate run must count firings and the rule ships only at 0. Sweet-expressions failed socially in Lisp, whose readers already read prefix; Baker's stated audience is designers and agents who do not (spec Appendix A, seexpr-vs-baker.md:102-115), and this corpus shows the band and the comparison are what they write.

**`expr-precedence`.** The same trigger as curly-infix (a brace whose slot 1 is an operator), but the whole brace is then an expression in a small C-like grammar with precedence, Pratt-parsed when the brace closes into nested head-first commands built in the load's arena: `{$v >= 0.3 and $v <= 0.7}` is `{and {>= $v 0.3} {<= $v 0.7}}`, and `{$x < $lo ? $lo : $x > $hi ? $hi : $x}` is today's clamp. It is the spelling spreadsheets and SeExpr taught every designer, and the runtime is still untouched; it costs a 200-line second grammar whose output the text never spelled, so it is the alternative to curly-infix, not its complement, and should be built only if curly-infix's corpus rewrite shows people nesting mixed-operator braces.

*Objection, and the proposer's answer:* Acton: 'You are adding a second grammar whose output the text never spells and the printer cannot restore, 200 lines against a 310-line headroom, for a transform with no measured consumer; the spec's read-this-twice section exists because uniform `{head args}` makes the evaluator and every tool trivial, and precedence is the first step toward the general-purpose language section 0 says Baker is not.' Honest answer: all true. The runtime is untouched and the output is ordinary commands, so nothing downstream changes, but the grammar is a real second thing for tools to re-encode (D220), the printer becomes lossy for expressions, and the corpus's wins are 90% covered by curly-infix's single rule. This proposal exists so the panel sees the full form and its price; the recommendation is curly-infix first and this only on evidence from the rewritten corpus.

**`self-dot-methods`.** A brace head that starts with `.` is a method on `$this` (`{.walk_to $obj}` is the tree `{$this walk_to $obj}`), a head `$obj.method` is a method on that object (`{$obj.walk_to}` is `{$obj walk_to}`), both parse-time rewrites, and a Property may head a command (`{[target] hit 1}`), one evaluator case. Handler bodies stop repeating `$this` on every line (34 of the corpus's 161 `$` uses are `{$this ...}` heads, all in Hearth's class) and read like method bodies to anyone from C#, Python or an engine's script, while the tree stays the talk's `{object method args}`.

*Objection, and the proposer's answer:* DTA heritage: '`{object method args}` is the talk's spelling; `.name` smuggles an implicit receiver, exactly the context-dependent reading s-expressions avoid; `{.walk_to}` outside a handler is a run-time error, not a check error; and it is the smallest proposal here, a convenience.' Honest answer: `$this` is already implicit context, a dynamically bound variable (D50); the rewrite is one-to-one with a form the language has and the tree is that form, so no reader of trees changes; outside a handler it fails exactly as `{$this walk_to}` fails today ('$this is not set'), and the class walker turns that into a check error, which is better than today. It is small on purpose: it is the one change that alters what a handler body looks like, which is where the harness vision wants non-programmers writing.

**`str-interpolation`.** `$"..."` is an interpolated string: `{say $"hp {$hp} of {[max_hp]}"}` is the tree `{say {str "hp " $hp " of " [max_hp]}}`, with `str` a new built-in that concatenates its arguments' printed text. The spelling is free today (`$` followed by `"` is the parse error '`$` without a variable name'), the holes are ordinary Baker text parsed by the same parser with real spans, and the result is an ordinary command, so check sees the holes, data_only refuses it as the computation it is, and the printer round-trips it. It is the lowest-priority proposal here: no site in the corpus needs it today, but the vocabulary has no string word at all (map 2 pain 13) and every behaviour log, console line and repro script that wants a value in its text has nowhere to put it.

*Objection, and the proposer's answer:* Acton and DTA: 'Nothing in the data asks for this; strings are data, and every data format that let a string become code grew a template engine; D126 made strings a memchr scan and holes are a second scanner; a third escape; and the budget is 310 lines.' Honest answer: the demand is thin and the proposal says so; the scanner runs only on `$"` tokens, never on data strings; the output is a plain command so no reader of trees changes; it should go last, after curly-infix and self-dot-methods, and only if the owner wants script to carry text at all (Hearth's behaviour log is the one consumer in sight).

#### Angle: the shape of the page

The shape of the page: a tuning file read the way a designer reads a spreadsheet and edited the way an agent reads a diff. Four changes to how the page is laid out and none to the tree underneath: the outer parentheses of a line give way to indentation (indent-lines); a keyed table declares its columns once and writes each record as a row of cells (column-tables); a layer file writes one path and one value per line (path-rows); a row's metadata sits in a right-hand margin behind bars (margin-bars). Each maps by reader-time desugaring onto the Array/Node tree Baker has today (the keyed record, the trailing metadata array, the nested layer) and keeps one byte span per value, so write-back, provenance, merge, layers, shapes, check, the cache, the console and the versioned JSON documents see the trees they see now; parentheses survive for anything inline, for commands and properties, and for any node that must span lines. Measured over the 68 .dta files (1,486 lines, 2,573 open brackets of which 2,219 are parentheses, 1,394 scalar leaves) with a tokenizer that honours strings and comments: 51% of parenthesized arrays open as their line's first token and close as its last; 21 keyed tables hold 120 rows and 414 (field value) cells; a leaf restated by an overlay costs 3.1 nested pairs on average and 5 for a Duel move; 334 trailing metadata arrays would become margins. The constraints the angle answers by name: round-trip and one spelling (the printer picks the canonical page form and the compact form stays bracketed), one contiguous token per value with a span (every cell, row value and margin value is still one token), tag-keyed merge (every form desugars to a tagged array), the pure-data tree with read-time expansion (headers and modes are directives, never nodes), the fixed layout (no Type, no flag, no header byte, kVersion stays 6), and the lexical reservation (no new atom-end byte; one reserved bare symbol, '|', checked against the corpus and to be checked against the raw gate).

**`indent-lines`.** A line that begins with an atom is an array: its tokens are the array's nodes and the lines indented deeper are its children, so the outer parentheses of every line go and the indentation every corpus file already keeps by hand becomes the structure. Brackets stay for groups inside a line, for commands and properties, and for any node that must span lines; a line that begins with a bracket is read exactly as today, so every existing file parses to the same tree. It is the right radical move because the corpus already has this shape (51% of its parenthesized arrays open at the start of a line and close at its end) and both writer and reader pay those brackets for nothing but the parser.

*Objection, and the proposer's answer:* The DTA-heritage objection: Harmonix's format is whitespace-free by design, so a file can be reflowed, pasted and generated without counting columns; the one layout rule Baker has ('#define N (' on the same line, D11) is listed as a wart in every map; making an invisible character structural invites the paste-from-elsewhere failure and the tab-versus-space argument, and a generator such as the Ledger exporter must now write indents or know that brackets still work. The Acton objection: it is work on the parser's hot loop for a benefit the parser does not have, and a per-token first-on-line test is a last-minute decision. The honest answer: brackets remain a complete spelling, so paste, generate and reflow with brackets as before, and the gate's 464 files do not know the rule exists; the rule is one sentence (a line that begins with an atom is an array of its line and the deeper lines), tabs are refused in indentation rather than guessed, and the printer canonicalizes so no file holds two styles unless a person wrote it so; the branch is taken on first-on-line tokens only and must measure under D143's precedent. It argues against spec section 1's implicit 'the parentheses are the structure' and says so: the corpus shows people already keep the structure in the indentation, and a reader that ignores it throws away data it was given (the acton-review skill's rule 6, 'don't throw away data you need'). The spec's robustness principle is untouched: a wrong indent is a located error or a different, still well-formed tree.

**`column-tables`.** A keyed table declares its columns once in a #columns header and writes each record as one row of cells keyed by its first cell, so Duel's five moves are five lines under one header instead of fifty (field value) pairs and a generated sheet (economy.dta) is written as the sheet it came from. The header is a directive, consumed by the reader and never in the tree, and each row desugars to exactly the keyed record Baker merges, checks and writes back today, every cell keeping its own byte span. It is the right radical move because the keyed table is the content convention (D142) and the corpus's heaviest shape (21 tables, 414 cells), and today every row restates the column names the row beside it just wrote.

*Objection, and the proposer's answer:* The DTA-heritage objection: positional data is what keyed records were invented to end, and the corpus's own pans/vols/cores lists (tests/corpus/songs.dta:15-17) show alignment nothing checks; a row of twelve numbers is readable only while the header is on screen, '_' is one more reserved spelling beside #remove's slot, and in a song table of thousands of rows the column names were the only thing a merge, a patch and a person could agree on. The Acton objection: 'if you have different data, you have a different problem' (slide 33): a reader that rewrites rows is a second path through close() for the page's sake, and the arena estimate no longer follows the brackets. The honest answer: the tree is the keyed record, not the row; positional is only the spelling, and the header is checked against every row at load (count) and the shape at check (types), which is more than today's record gets; the reserved spelling is one symbol in one position, like #remove, and the printer never emits it; the rewrite runs only in frames that have a header, and its cost is the arrays the nested form already makes. What it does not do, said plainly: it gives a layer no way to override one cell except the nested form or a path row, and it does not type the columns, which is the shape's job; a header that is also the shape (map 3 opp 0, 'declare the shape at the table it governs') is the obvious next step and is kept out of the day.

**`path-rows`.** A layer file that opts in with #paths writes one path and one value per line, 'fighters.kestrel.moves.jab.startup 5', the spelling the console, diff, explain and every error already use, instead of restating the whole nesting from the root; the reader folds the rows into the nested tree a Config merges today, each leaf carrying its row's line. It is the right radical move because the files people and agents write by hand are layers (local, agent, overlays), layers are sparse, and a sparse file should read like the diff it will become: a Duel move value costs five nested pairs today, and the stacks' own test overlay ten parentheses for three values.

*Objection, and the proposer's answer:* The DTA-heritage objection: a dotted atom is an ordinary symbol in DTA (duel.win_rate, sfx/tambourine_bank.milo, and 'boss.restart_phase' is the spec's own naming convention for pack words), D27 already carries the awkwardness that a key with '.' must be quoted in a path, and #paths makes that quoting rule reach into data files, where a tag like v1.2 silently becomes two keys; it also gives the language a second shape for one tree, so a reader of two layer files must know which each is. The Acton objection: a load-time fold is work the base never needed, and 'different data is a different problem' says a sparse layer and a dense base should not share a reader. The honest answer: the mode is per file and opt-in with a visible first line; the quoting rule is Path's, which every console user already meets, and a dotted tag in a rows file is caught where it is written (a located refusal under existing_only or scalars_only, and otherwise a new key the shape warns about, exactly as a misspelled nested key is today); the fold is the merge the Config does anyway, done once per load of a file that is sparse by nature, and the base keeps the dense form, which is the 'different data, different reader' answer stated rather than denied. It argues against nothing in the spec; it argues against the cookbook's 'restate the path' idiom for overlays (docs/cookbook.md:468-481) and says so. The deeper limit, said plainly: rows hide the table, so a file of rows is for what a person or tool changes, not for what they read whole.

**`margin-bars`.** A bar '|' on a line opens a margin: the words after it, to the next bar or the end of the line, are one tagged child of the line's array, so a tuning row reads 'hit_pause 6 | range 0 30 | desc "..."' and a shape field 'startup int | range 1 60 | kind frames', the value in one column and its metadata in the margin where a spreadsheet keeps its notes. The tree is unchanged: a margin is exactly the trailing (range 0 30) array Baker reads today. It is the right radical move because a fifth of the corpus's atoms are metadata (map 5: 19.5%) written in the same brackets as the values they describe, and the page can show the boundary the tree only infers from a reserved-key list (D88).

*Objection, and the proposer's answer:* The Acton and spec objection together: this is sugar; the tree is byte-for-byte what (range 0 30) builds, so it fixes none of the value/metadata ambiguity (pain 1, D88, D218), spends a reserved symbol and a layout rule, and adds a second spelling of the same node that the printer must canonicalize, which the one-spelling ethos of D13 and D226 and the modding expectation of a whitespace-free DTA file both weigh against; a bar meaning 'child to the end of the line' inside a bracket is a new kind of rule for a grammar that has one. The honest answer: yes, it is the page and not the tree, and the proposal claims only the page: the boundary that merge, tweaks and shapes already infer is drawn where a person can see it, the sugar desugars at the frame, costs one compare per symbol, and no reader downstream knows it happened; the layout rule is the one indent-lines brings (a line is a unit) and is stated once. The path it opens and does not take: if a later change gives the Array a real boundary (map 6 opp 1: a split index in the header, which D28's sorted mode would have to respect and the 24-byte header has no room for today), the bar is its spelling and no file changes. Dropped on evidence: if the raw gate finds a bare '|' in a Harmonix file, the bar is reserved on indent-lines' Lines only, where no raw file can be.

#### Angle: types and literals

Types and literals: inline type and range annotations where the value is written, unit and kind suffixes as literals, booleans, inline enumerations, shapes declared where the data is, and metadata as attributes; the Halo-tags premise that the data describes itself, held against D88, the 16-byte Node, the reference JSON and the tuning panels.

**`at-attributes`.** Metadata becomes an attribute by construction: a trailing child tagged `@key` (`(@range 0 30)`, bare `@optional`), counted in the Array header, so `Array::values()` is the value and `attributes()` the rest for every reader, not only for tweaks. The seven reserved words stop being reserved (D88's closed trailing set becomes one sigil bit), `(ball (kind ball) ...)` and `(desc string)` can never be misread, `get<std::array<float,3>>` of a ranged color works, and a misspelled attribute is a warning instead of a value silently ignored. It is the change the other three proposals in this angle build on, and it needs no lexer change: `@` is already atom content (src/data/text.hpp:44-49).

*Objection, and the proposer's answer:* Acton: "You spend header bits and a cache version to rename a convention. D88's trailing rule works, split_metadata is 12 lines, a sigil is another convention, and the external corpus has `@`-led atoms." Answer: the convention is by name, and the names collide with real vocabulary today (the critic's pain 1, the strongest single pinch, 19.5% of all atoms sit in metadata); a sigil moves the decision from seven string compares in four readers to one bit set at intern time, and makes `values()` exact for every reader, which no discipline about trailing order gives `get<std::array>`. The bits were free, the bump is one line and `baker_bake` re-bakes. The gate: an `@`-led atom in a raw Harmonix file is a value that now needs quoting; the 41 s run counts them and the D-entry records the number; if it is more than a handful the sigil becomes `~`, ruled on by the same count. The spec is not contradicted: spec section 4 says metadata "may equivalently live in the data file, matching the slide syntax"; the slide's spelling changes by one byte.

**`literal-forms`.** A number may carry its unit (`4m`, `30f`, `45deg`, `15%`, `1.4m/s`), a boolean is `true`/`false`, a color is `#ff8800`, and a hex int remembers it was written in hex, all in the Node's seven reserved bytes with no new Type. The unit is a claim checked against the shape's or tweak's kind, never a conversion, so a value is read exactly as today in one load; what changes is that 62 desc strings stop spelling units in prose, booleans stop being three idioms plus a per-project macro, hex flags round-trip as written, and `(angle 45m)` is an error before the game runs.

*Objection, and the proposer's answer:* DTA heritage and D101: "The owner refused two lenient lexing rules that fixed 9 files because they would hide a stray quote; `12abc` becoming a number is the same kind of guess, `true` as a reserved word breaks any Harmonix file that uses it as a symbol (D85 chose macros for that), and a unit is metadata: `(kind ...)` already exists and the library 'attaches no behavior to it' (spec section 4)." Answer: the unit grammar is stricter than today's fallback, not looser: a digit-led atom with a letter tail is a unit-number or nothing, and the 464-file run is re-run and its count recorded before merging; raw files holding bare `true` or letter-tailed digit atoms get quoted by the rule that quotes `'12'` today. `(kind ...)` tags a row; it cannot tag `(pos 4.5m 30deg)` or `(hours 7h 21h)`, and nothing checks it, which is why 25 shape fields write it and no error has ever come from it. The spec forbids nothing here: it reserves the padding, and the reason is now measured. The honest limit: a unit is checked, never converted; `15%` is 15, and a host wanting 0.15 writes 0.15 or declares the field's kind as `%`.

**`typed-rows`.** The row is its own declaration: `(speed:float 4.5 0..10 (@desc "..."))` writes the type on the key and the range as a literal, so a tuning row, a shape field and a tweak are one grammar, a declaration being a row without a value. `check` holds every typed row to its own type, arity, range and choices with no shape, no registry and no game binary; the 47 C++ TweakMeta copies that drift from the data go; and 328 positional vectors can say their arity (`hitbox:float4`) instead of carrying it in prose. This argues against seexpr-vs-baker.md's "static typing not adopted" and knows it: that verdict was about script and a compiler, this types data rows, which spec section 6 already does, at the row.

*Objection, and the proposer's answer:* Spec and DTA heritage: "'Static typing and a compile step' were considered and deliberately not adopted (seexpr-vs-baker.md:233-236); a tag is one atom and the tree is the text, so splitting `name:type` and synthesizing a child the author did not write breaks the simplest fact about DTA, and every text tool (tree-sitter, the harness's quoting rule) must learn the split." Answer: what was declined was typing script for a compiler; this types data rows, which shapes already do (spec section 6), and only moves the declaration to where the value is, where provenance, write-back and the agent already look. The synthesized `(@type)` is the reader-side desugaring the survey names as the one route that leaves the runtime untouched (constraint 9), the printer reverses it, and `parse(write(t))` equals `t` with one spelling. The real cost: a `(` tag's text and its Symbol differ for typed rows, so read_structure reports the token as written plus a `typed` flag, and a text tool needs the same one-line `:` rule. If the gate finds a raw Harmonix tag ending in `:` plus a type word (implausible, uncounted), the separator becomes `::`.

**`tables-declare-rows`.** A table declares what its rows are, where the rows are: `(fighters ... (@each fighter (health:int 1..100000) ... (moves:table (@each move ...))))`, and `(bots (@each cpu_level))` reuses a declaration by name. `(shapes ...)`, `(at fighters * moves)` and `(keyed)` go: the governed path is the declaration's own place in the tree, so a shape at the wrong depth cannot exist, a pack file declares by mirroring the data's structure and merging by tag, and a nested table is declared inside the row type that holds it instead of by a path with a `*`. It deviates from spec section 6's `(shape name ...)` and from D84's container, and says why: both answered top-level merge-by-tag, and attributes answer it at every level.

*Objection, and the proposer's answer:* D84 and the Acton lens: "The `(shapes ...)` container exists because the top level merges by tag (D84 replaced the spec's `(shape name ...)` for that reason); declarations beside data mix schema and content in the file the agent edits; and a tree walk per layer per merge is work the bake should do once." Answer: the container solved top-level merging by putting declarations in one tagged array; attributes solve it by putting each declaration on the array it governs, which merges by tag at every level already (constraint 3) and gives D145 the same per-field, per-file rank. Nothing forces schema into the data file: a pack's `(fighters (@each fighter ...))` is an attribute-only mirror that merges onto the data, so the review split (packs by PR, data by the agent) is kept and `(at ...)` is replaced by structure, not by proximity. The walk is bounded by a subtree flag computed in the pass that already computes height, runs where `Set::add` runs today (per merge, off every hot path), and stays only if the shape benchmark says so. Given up honestly: a declaration's place is its governed path, so one shape cannot govern two unrelated paths except by name reuse (`@each NAME`), which is the reuse the stacks ask for (map 3 opportunity 1) and not an `at` list they do not.

#### Angle: keys, paths and references

KEYS, PATHS AND REFERENCES: a tagged array's key as a path (flat rows that merge into the tree), values that reference other values by path, prototype records (fill-missing from a path, the in-tree form of #merge), and key references that must exist. One sigil family: `@path` is a place in the tree (as a key: where this array goes; as a value: what goes here), `&path` is the name of a key that must exist. Nothing changes the tree's ten node kinds, the 16-byte Node, the tag run, the cache format or the lexer's atom-end table; rows are desugared by the reader, references are resolved by the Config at merge, and both are measured against the survey's constraints 1-7 by name.

**`path-rows`.** A tagged array's key may be a path: `(@fighters.kestrel.moves.jab.startup 5)` is the same tree as the five nested arrays, built by the reader and folded into its siblings. Overlays, patches, personal, agent and live-ops layers become one row per value, spelled exactly as the console, `diff`, `explain`, errors, `unsaved()` and write-back already spell that value, so the one text form every tool prints is finally one a person can write back. Nothing below the parser changes: merge, lookup, provenance, shapes, check, the cache and the JSON documents see the nested tree they see today.

*Objection, and the proposer's answer:* The Acton-school objection: two spellings for one tree is a transform with no runtime benefit, placed in the parser (40% of a parse is the lexer, D199) for the benefit of the rarest files, and a merge inside the reader (the fold) blurs the line between parsing and layering that D31/D32 keep clean. The DTA-heritage objection: a DTA key is the symbol in slot 0 and `(a (b (c 1)))` is how every Harmonix file says `a.b.c`; a key that is a path adds a sigil beside `$`, `#` and `'` and reads like a different language in the same file. The honest answer: the tree keeps slot 0 a Symbol exactly, so every reader below the parser is untouched and the gate holds by construction; the cost on files without rows is one predictable compare per array, measured, not asserted; and the spelling is not new to Baker: it is the one every error, tool, console and journal already prints, which the survey's pain 2 shows people re-nest by hand five parentheses deep. What is really given up: a row cannot reach a quoted or indexed key, and a frame with rows merges where a frame without them does not (later wins vs first wins), which is a second duplicate-tag rule the language guide must teach in one sentence.

**`at-refs`.** A value may name another value: `(master_volume @defaults.volume)` holds, after the Config merges its layers, the values the merged tree has at `defaults.volume`, shared by reference, with provenance that names the reference's line and an `explain` chain to the target. It replaces the corpus's value-macro idiom (`kDefaultVolume`, `RED`) with something that layers, provenance, write-back, caches and tools understand: a path. No new node kind, no lexer change, no cache bump; resolution is one walk at merge, never work at read, so the tweak read stays one load and the digest is that of the plain values.

*Objection, and the proposer's answer:* The Acton-school objection is the strongest: late binding is the thing a data-oriented engine avoids; a value that lives "somewhere else" is an indirection, the resolver is a tree walk on every merge, a layer's meaning now depends on the whole stack, and D8 recorded that Baker does not build evaluation machinery "for a workload Baker doesn't have". The DTA-heritage objection: macros are the original's way to name a constant, they expand at read so a file is self-contained and a bare `read_file` sees the real numbers, and spec Appendix A promises exactly that macros "multiply-reference the same" value. The answer: the indirection is paid once per merge, which already rebuilds every changed array, and never per read; the merged tree is as flat as a hand-written one and the digest proves it; a layer already depends on the stack (it merges into it), and a reference is the first thing in the text that says so where a tool can see and check it; sharing keeps Appendix A's promise without splicing at read. What is honestly lost is self-containment: a file read outside a Config holds symbols until `resolve_refs` is called, and that is a new step for every tool that reads one file (the stacks' exporters, results.dta's reader). If the judges weigh that as fatal, the fallback is resolution at the end of each file's parse against that file alone, which keeps self-containment and loses the cross-layer payoff, the half that macros could never give.

**`proto-records`.** A reference to a record is a prototype: `(brute @enemies.grunt (hp 50))` is grunt's record with brute's own keys winning, filled in at merge with the fill-missing rule Baker already has for `#merge` (D1, D15) applied to a path instead of a file. It is the DTA idiom of app-over-defaults brought to record granularity, in-tree, layer-aware (a DLC retuning grunt retunes every inheritor, a DLC setting brute.speed wins), with provenance per field and write-back that overrides rather than guesses. It gives shapes reuse without a type system: `(bot @shapes.cpu_level (at bots) (keyed))`.

*Objection, and the proposer's answer:* The Acton-school objection: prototype chains are the classic way data turns into a program; "where does this field come from" becomes a walk; a diamond's first-wins and a chain's 32 hops are rules a reader must hold in their head; and spec §4's `#merge` exists for the original's app-over-defaults reason (D1), as a file-level idiom, not as a modeling feature, so this proposes a feature the spec never asked for on top of a mechanism it kept for compatibility. The DTA-heritage objection: Harmonix records are flat and explicit, and the format reached thousands of songs with keyed tables and macros, never inheritance; `(bot @shapes.cpu_level ...)` is not DTA. The answer: the walk is once per merge and bounded, never per read; provenance is answered by the supplier rewrite and `explain`, which no macro and no hand copy gives; the fill semantics are literally D1's, already in merge.cpp, applied to a path instead of a file; and the repository's own evidence of the need is in its schemas (two shapes declared twice, with drift) and its matrices (seven scenarios), not in gameplay records, which the design note must say plainly: no stack's data needs inheritance, its shapes and harness files do. The honest weakest point is the audit's close-mapping value: a record that inherits is not whole on the page, and if the judges rate that above shape reuse, prototypes should be allowed only inside (shapes ...) and harness forms, which the prototype can measure by counting where the samples use it.

**`key-refs`.** A symbol that names another key says so: `(cancels &.jab &.low_kick)` is checked at every merge against the table the record lives in, and `(lay &pieces.straight_40 ...)` against the stack, with a located warning and a check-gate failure when the key is missing; the game reads plain symbols exactly as it does today. The survey's pain 5 is that references between rows are bare symbols nothing checks, so a typo passes `check` with exit 0 and the agent loop reads it as "go on"; this answers it in the data file with no shape, no C++ and no new node kind.

*Objection, and the proposer's answer:* The strongest objection is from the shapes angle, not Acton: a shape field typed `(cancels (list (ref fighters * moves)))` (map 5 opportunity 3) checks the same thing once, in the declaration, with no new lexeme, no sigil on every use site, and it can also type `(objectives ...)` across file sets and handlers against the autorun list, which `&` cannot; and DTA heritage says references in data are bare symbols by design, so `&.jab` beside `jab` is two spellings of one name and a relative scoping rule the format never had. The Acton-school objection is mild (one walk per merge, no read cost) but real: it is runtime work to verify what a schema could verify at bake. The honest answer: shapes are opt-in, live in a separate pack file reached by `#require`, and 22 of 121 stack fields are `any` today, so the schema route checks nothing until someone writes the schema at the right depth (map 3 pain 1); `&` works in the data file alone, says at the use site what the author meant, and the two compose (a shape ref type may require `&`, and a `&` may be checked against a shape's `at`). If the judges adopt typed shape references, key-refs is redundant except for stacks without shapes, and the prototype exists to measure exactly that: how many of the stacks' references each route checks, with the same samples.

#### Angle: layers, patches and time

Layers, patches and time as syntax. A layer is the product (live ops, DLC, mods, the personal local layer, an agent's proposal), yet the only written layer operations are "restate the nesting and replace" and (key #remove). Give the operations a written form that is one grammar for the layer file, diff, explain, the journal, write-back and the console: rows addressed by path; list and numeric markers beside #remove with promote able to write a removal; layers, conditions, experiment arms and validity windows as blocks inside a file instead of #ifdef, a second file and a C++ toggle; and patches that carry the base value they were made against so a stale overlay or agent edit is caught where it is staged. Each proposal leaves the tree pure data with the ten Types, keeps today's .dta parsing, and names where it argues against D142/D138 gap 36, the spec's "a layer is a file", and the Acton bake-time rule.

**`patch-rows`.** A layer is a patch, and a patch should name what it changes by path: `(@fighters.kestrel.health 1100)` is a row whose head is a Baker Path and whose tree is exactly the nested `(fighters (kestrel (health 1100)))`, synthesized at read. Every leaf of the stacks' data sits 3.4 levels deep on average, so an overlay, an agent layer or a local layer restates 6.8 parentheses per value today while diff, explain, the console and write-back already speak the flat path. Rows make the layer file the same sentence as the tools, and because the tree is unchanged, merge, provenance, the cache, LayerPolicy, promote and write-back need nothing.

*Objection, and the proposer's answer:* Acton: a second spelling of one tree is a transform paid at every read, and two ways to write one thing is the pain this survey names (two macro spellings, three booleans). DTA heritage: DataArray files are trees; a flat row file is another format the printer cannot reproduce, so round-trip is structural only, as hex already is. Honest answer: the transform is paid only by rows (a byte compare otherwise, to be measured), and rows are not a second way to write data but the first way to write a patch: the files that are patches by nature (handheld, bosses_patch, agent, the four overlays: 7 of 68) hold no deep trees, while base files stay nested. The printer's structural round-trip is the contract (write.hpp:3-7) and is kept; a rows mode is added for the tools that emit patches, and write-back never reprints a file. What rows do not solve: an element or a name with spaces cannot head a row, and the gate must be re-run for `@`-headed arrays.

**`layer-markers`.** `(key #remove)` is one verb of a merge language the layers never got: give layers `#append`, `#drop` and `#scale` beside it, as the same slot marker, header flag and printer rule D143 built, so a DLC adds a song, a patch drops a cancel, a weekend scales a drop rate by 1.5 without knowing the base, two packages extending one list compose in stack order, and promote writes a removal by deleting the key's extent instead of refusing. The owner declined an append marker twice (D138 gap 36, D142) in favor of keyed tables; this argues that the stacks' own lists (cancels, items, things, blocks) are ordered and unkeyed by nature, and that an explicit verb is exactly what D142 said a warning could not supply.

*Objection, and the proposer's answer:* D142 and D138 gap 36 are the owner's decision, twice: keyed tables are the convention, there is no new syntax, and replacing a list is also the normal way a patch changes a value, so a warning could not tell the two apart; the spec leaves out a list-append marker by name (spec near line 926), and Acton asks why a merge should compute (`#scale`) what a bake could. Honest answer: the decision stands for records (songs.dta scales because a song is a record), but a cancel list, an item list and a wall list are ordered sequences that a keyed table would misdescribe; D142's own reason is the argument for a marker, since a marker is the author saying "extend", which no heuristic could infer; and D143 already paid the whole mechanism (the slot rule, the bit, the printer exception, the policy rules, the fuzz case) for one verb, so three more are a generalization, not a second mechanism. `#scale` is the contestable one: it moves arithmetic into the merge (a reload-time path, never per frame) and its result type must follow D14; if the owner refuses it, `#append` and `#drop` stand alone. Shapes still judge the merged result, so a composed list is as checked as a restated one.

**`inline-layers`.** A layer is a file today, so a platform variant is a second file, an experiment is a pair of files and a C++ toggle, and a conditional is a token-level #ifdef no tool can see or fold. Let a file declare layers inside itself: `(#layer (handheld (when HANDHELD)) (renderer (shadows 0)))` is a bracketed block the parser lifts out of the tree into the session as a sub-layer of its file, which the Config pushes directly above the file as `default:handheld`: toggleable, explainable, cached and reloaded with the file, placed with it, written back into by its own extent. A block's options give it a condition, a disabled start, a dev_only mark, an exclusive group (experiment arms) and a validity window the host applies with its own clock, so the live-ops overlay's "ships Friday, roll back Monday" comment becomes data.

*Objection, and the proposer's answer:* Spec and heritage: a layer is a file (spec §4; the cookbook's version-history rule that the layer's name is the file's name; D32's provenance from the layer trees; D35's reload from the lowest changed layer; caches per layer path); blocks make the stack diverge from the project file and the file list, and #ifdef was kept at D101 because the raw corpus uses it. Acton: a condition decided at bake (#ifdef, one expanded tree per define set) becomes a layer merged at every stack change, and a window is runtime work for a calendar. Honest answer: a block is a sub-layer of its file, named by it, read, cached, reloaded, placed and removed with it, so every file-level rule holds at the file and the project file still lists only files; #ifdef stays for raw DTA and is not taught. The merge cost is one small layer per block at reload time, never per frame; the window is a recorded option and one host-called toggle, not a clock in Baker. The real costs are the cache bump and the line budget, which is why this proposal is prototyped last or with a budget decision; and a block cannot hold directives, so a conditional #include stays #ifdef's alone.

**`pinned-patches`.** A patch is made against a base, and today the base is nowhere in it: an overlay checked against game_data "1.0" (D147) still lands on a value a person retuned since, an agent's agent.dta written from last week's diff silently overrides a number a designer changed live, and promote --patch shows the `-` line only at the moment of promotion. Let a row carry the value it expects below, `(@cpu.easy.reaction 26 #was 30)`, as a trailing marker the merge strips and check_layer compares, so a stale patch is a located warning at stage time and a refusal under warnings_refuse; diff, write_back_to and the journal write `#was` for free, and a row's `(note "...")` rides into promote's patch, so the reason for an edit has a structural home.

*Objection, and the proposer's answer:* Acton: a pin is runtime bookkeeping for a question the stack already answers live, since layer_effect's `below` is the base at any moment and git holds the history; pinning rows to values strands every overlay on every base retune, and a stale value is often exactly the value the patch meant to set regardless. Heritage: DataArray values are values; a value that remembers another value is a diff format, not data. Honest answer: `below` is now and `#was` is then, and the difference is the one fact a staging step cannot otherwise know; the pin is optional per row, a warning by default, a refusal only under warnings_refuse, and never changes what the merge produces, so an overlay that means "set it regardless" omits it. The real limits: `#was` pins values, not structure (a renamed key reads as a new key, which existing_only already refuses), and a pin on a command value compares structurally, which is right for `{* 30 $difficulty}` and meaningless for a value computed at read.

#### Angle: machines: agents, tools and diffs

MACHINES: AGENTS, TOOLS AND DIFFS. The .dta files as an LLM agent writes them, a tool reads or emits them, a console edits them, and a reviewer diffs them in a pull request. Today the file speaks nesting while every tool (diff, explain, the journal, errors, config.set, promote --patch) speaks a flat path; the agent translates by hand (stacks/tools/test_commands.py:124 vs :222), promote drops the agent's reason (tests/host/test_commands.py:100-104), the printer cannot keep a comment, and inserted blocks differ in shape from the file around them (config_write.cpp:64-76, 275-285). The four proposals below each change how a file is written so that a line of the file is also a line of a tool: a path row, a table row, a doc comment, and one layout. All four leave the tree, the merge, the cache, the digest and every reader of the tree untouched; the surveyed hard constraints 1-6 hold by construction, and each names the measured gate (constraint 7) and the tool surfaces (10) it must re-version.

**`path-rows`.** A parenthesized array whose bare tag spells a path (it contains '.' or '/') is a row: the reader expands it into the nested tagged arrays the path names, so `(cpu.easy.reaction 26)` is the same tree as `(cpu (easy (reaction 26)))`. The line an agent writes in agent.dta, the line `diff` prints, the path `explain`, errors and the journal name, and the line typed on the console become the same bytes; the console accepts a row as an edit, `promote` can finally write a removal, and an overlay is one line per value. It is the right radical move because the flat path already exists everywhere except in the file, and it is the file that agents and reviewers read.

*Objection, and the proposer's answer:* Acton school: 'The reader now interprets a name. DataArray never looked inside a symbol; a tag with a dot silently changes meaning; the printer gains a second positional quoting rule beside the #remove one; and the fold is a merge inside the parser, paid on every file for a feature overlays use.' DTA heritage: 'Dotted tags may exist in the 464 raw files; the gate is run by hand and nobody will notice.' The honest answer: the two spellings already exist, and the translation between them is done by agents and people, by hand, at the exact place review happens; the file is the one surface that does not speak the path, and the dot rule is Path's own rule (D27: a key with '.' or '/' must be quoted there too), so after this the file and every tool agree for the first time. The per-tag check is one scan and is measured, with the intern-time bit as the fallback; the fold runs once per frame close, only when the frame held a row, and the tree every reader sees is unchanged. The quoting rule in tag position is the same function paths already use (append_path_name), not a new predicate. On the gate: it must be re-run and the count recorded in the D-entry, as D101 was; if raw Harmonix tags with dots exist, the owner chooses, and the proposal says so rather than hiding it behind a session switch.

**`columns-tables`.** A `#columns (name ...)` directive inside an array declares the fields of the rows that follow; each row writes its cells positionally after its key, and the reader expands them into the tagged children every reader expects, so `(jab light 4 2 7 30 ...)` under `#columns (button startup active recovery damage ...)` is the tree `(jab (button light) (startup 4) ...)`. A keyed table becomes a table in the text: one row per line, a cell is one token, a misspelled key is impossible, a cell count mismatch is a parse error, and a spreadsheet export writes cells instead of restating every key on every row. It is radical because DTA has never had a positional record with named fields; it is right because the stacks' tables are already written as tables by hand, at 110 to 135 characters a line.

*Objection, and the proposer's answer:* Acton school and the cookbook: 'This is a positional record, the thing keyed tables were chosen over (D142; cookbook: anything packages extend is a keyed table); a reader counts columns to know which cell is damage; the header is a second declaration of the shape's field list that will drift from the pack; and DataArray never had a table.' Answer: the rows stay keyed by their tag, which is what merge, layers and shapes key on; only the cells are positional, and only in the text: the tree, the merge and every reader see `(jab (damage 30))`, so nothing packages extend changes shape. The header declares the one thing the shape cannot, the order, because shapes are read after the parse by a separate library (spec section 6, D84) and cannot drive expansion; a later `check` can hold the header to the shape's fields, which is a tool's finding, not a parser's. Counting columns is what a spreadsheet reader does, and the economy table is already a spreadsheet, exported into lines nobody can read at 135 characters. The cost is nothing for a file without the directive, which is every file today, and that is measured.

**`doc-comments`.** A comment that begins with `;; ` is a doc comment and one that begins with `;! ` is a note comment: the reader makes it the `(desc "...")` or `(note "...")` of the parenthesized array it ends the line of, sits inside, or precedes. The 47 described tuning rows, the 60-odd shape fields and the records with a `desc` field read as commented lines and are the same data; and the reason an agent writes beside an edit becomes a note that promote writes into default.dta as a comment on the value's line, so the reason reaches review and git blame instead of being dropped. It is radical because the spec keeps comments as trivia; it is right because every tooled language ended up putting documentation in a comment with a sigil, and Baker's tools already read `desc` and `note` by a reserved key.

*Objection, and the proposer's answer:* The spec, knowingly: it keeps comments as trivia discarded in gameplay mode (spec section 1, Edit-mode parsing; the 'not building' list and D8 leave comment-embedded metadata out), and the DTA heritage reads `;;` as a banner in forty years of Lisp and DataArray files; the Acton school adds that a comment that changes the tree makes the lexer look at comments it used to skip with one memchr. The honest answer: the reason to keep comments as trivia was to keep the gameplay tree lean and the lexer dumb, and both stay: the tree gains exactly the `(desc ...)` child the data would have written by hand, in the slot D88 reserved, and the lexer's new work is one compare on a comment and a peek after `)`, measured. It is less embedded than today, where a tool must know a reserved key list to find a description; a sigiled comment is where Rust, Go, Python and Kotlin put one, for the same reviewers. The banner risk is answered by the space rule and by the corpus count, and the spec's rule bends for two sigils only; `;` stays trivia.

**`one-form`.** Baker defines the one layout of a .dta file and writes it: `baker::format(text)` keeps every byte that means something (tokens as spelled, comments, directives, macro definitions, conditionals, the author's line breaks) and owns every byte that does not (indentation, spacing, key and cell alignment, trailing-comment columns, blank lines), as gofmt does; the printer's defaults become that layout so an inserted entry matches the file around it; `check` reports a file that is not in it, and `baker_fmt` rewrites it. It is the change that makes a diff a diff: no reviewable change is ever a reflow, every leaf is one line with its path as its identity, promote's patch and a hand edit produce the same bytes, and the tolerant read can resync at the next column-0 form. It is radical for DTA, whose files are hand-laid-out, and right because the stacks already hand-align every table and the library already fails to match them.

*Objection, and the proposer's answer:* Acton school: 'A formatter is a tool, not the language; 220 core lines for whitespace when 310 remain, and the printer already has a form; and a check finding about layout is bureaucracy in a library that promises one line per tweak.' DTA heritage: 'Harmonix files are hand-laid-out and the modding community edits them in Notepad; a canonical form reformats their work and makes every file look alike.' Answer: the formatter is what makes the other three proposals' forms one form instead of three more ways to lay a file out, and it is the cheapest tool Go shipped and the one that ended the most arguments; the library already writes layout (render_entry, promote, write_file) and today writes it wrong against its own house style, so the question is only whether the layout rules live in one place or in each writer. Nothing on a load path pays for it, the budget cost is stated, and the owner can keep format.cpp outside the core as shape is. On heritage: format is never applied by a loader, the raw gate is parse and round-trip, and a modder's file stays legal input; what changes is that the files Baker itself writes, and the files a studio checks in with the finding on, have one shape.

#### Angle: heritage, evolved

HERITAGE, EVOLVED: DTA 2. Keep what the slide deck and twenty years of modders made identity: parens are data, braces are lazy commands, $var, '#' is the reader's namespace, [NAME ...] at the top level is a macro, the tag is the first symbol and layers merge by it, the atom-end set is tiny so symbols may hold . / : -> >=, strings end at the first '"' because the only escapes are \q and \n (one memchr finds the end), the quote is a quote only at an atom's start. Fix what was accident, each in one deliberate step: two macro spellings with a same-line rule, '#' meaning three things, an unprintable apostrophe, numerals that are symbols unless they overflow, TRUE/FALSE as macros every project copies, hex that prints decimal, declarations recognised by position and String-sniffing, a (shapes ...) container forced by the top-level merge, a hitbox whose arity lives in prose, metadata told from data by a seven-word list that collides with real fields, and definition forms read by position. Every proposal ships with tools/migrate_dta.py, a span-preserving rewriter with a frozen DTA-1 tokenizer (outside the core budget) that migrates the 68 in-repo files and the docs' 24 dta blocks, and is run over the 464-file raw gate before baker_parse_corpus so the number is re-recorded, never assumed.

**`one-macro-one-hash`.** DTA's `[NAME ...]` is the macro definition and the only one; `#define NAME` defines a flag and nothing else, so the grammar's single layout-sensitive rule (parse.cpp:881, D11) goes and a `#define` with a body on the same line is a located error pointing at `[NAME ...]`. `#` opens a directive only before an ASCII letter, so `#`, `#1`, `#00aa00`, `#$%&` are symbols the printer writes bare; `''` inside a quoted symbol is one apostrophe (doubling, no backslash, the scan stays one find); and a numeral too large for int64 or double is a symbol like every other atom that fails to lex. This is the lexical DTA a Harmonix engineer would sign: one spelling per thing, nothing read by layout, the \q/\n strings and the atom-end set untouched because they are the format's identity, not its accident.

*Objection, and the proposer's answer:* Heritage: "Harmonix's own files use `#define NAME (body)`; that is why D11 carries the same-line rule, and the raw gate (464/464, run by hand) falls until every file is migrated." Answer: the gate number is re-recorded after a span-preserving migration that keeps the raw text reviewable; the parser never guesses (a located error points at `[NAME ...]`, so an unmigrated file fails loudly, not silently as a flag plus data); and `[NAME ...]` is the spelling the slide deck and every modder know, so the heritage spelling wins over Baker's second one. The owner chose strictness over lenience in D101 (two lenient rules reverted); this proposal removes a rule rather than adding leniency, except for overflow, where the alternative, a fatal error for a 20-digit bare name while `12abc` passes, is the asymmetry nobody defends. Acton: no hot-path instruction, fewer parser states, no new node kind, measured.

**`true-false-hex`.** `true` and `false` become literals that are Int 1 and 0 with a remembered spelling, and a hex literal remembers that it was hex: one of Node's seven reserved bytes holds the spelling, every reader stays an int reader, structural equality and the digest (D222) ignore it, and the printer writes what was written. DTA's `[TRUE 1]` macro was a stand-in for a literal the language lacked and every project copied (tests/corpus/macros.dta:3-4, D85); this is the literal, with no new node kind, no evaluator change and no change to what `bool` means to shapes, tweaks or `{== $value 1}`.

*Objection, and the proposer's answer:* Acton: "A spelling byte is presentation in a value tree; D18 chose 'hex denotes its value' and the printer canonicalises on purpose." Answer: the byte costs no size and no instruction on any read path, is ignored by equality and the digest, and buys the minimal-diff promise for exactly the two spellings real files use for flags, colours and booleans; the alternative, a Type::Bool, touches every ten-kind switch, the data-only policy, check and the cache for less. Heritage: "TRUE and FALSE as macros were DTA's way, and D85 chose numbers deliberately." Answer: they were a workaround copied into every project because the language had no literal; a literal that is still the number keeps D85's semantics (bool is an int) and ends the copying. Spec: section 1's node table lists no Bool; this adds none.

**`declare-directives`.** Everything a file says to the reader rather than to the game moves into the `#` namespace DTA reserved for exactly that: `#pack (...)`, `#origin (...)` and `#shape (...)` are directives taking one parenthesised form, recorded in the session like packs, origins and macros already are, and never in the tree. Position-and-type sniffing ends (parse.cpp:598-607 goes: `(origin 0 0 0)` is data anywhere, `pack` is a free tag, a second declaration is a located error instead of silent data), the `(shapes ...)` container goes because a declaration no longer has to survive a top-level merge by tag (D84's reason), and a `#shape` written inside a table governs that table's children with no `(at ...)` to restate and no `(keyed)` to forget. A list type gains an arity, so a hitbox's four floats are four.

*Objection, and the proposer's answer:* Heritage and D84: "DTA's `#` is a preprocessor; a shape is a schema, and Baker made shapes data on purpose so that layers merge them for free and tools read them from the tree." Answer: D84 chose the container only because the top level merges by tag and there was no other place; packs (D82) show the other place, the session, and Set::add already is the merge rule for declarations (a later declaration replaces or narrows); a declaration is a reader-time fact like a macro, and `#` is the one spelling DTA gives reader-time facts. Acton: "More session state to replay from a cache and to compare in shipping, and a disabled layer's declarations need a re-read." Answer: that is the price packs pay today, the merged tree gets lighter on every push, both measured on bench_config and bench_cache, and the toggle re-read is counted against the stacks' real layer counts (three layers each). Spec: section 1 writes `(pack ...)` and `(origin ...)` as forms and section 6 `(shape name ...)` at the top level; this deviates from both on purpose, for the reason D84 and D91 already recorded, and says so.

**`at-metadata`.** A tagged child whose tag begins with `@` is a word for the reader, never a data key: `(@range 0 10)`, `(@desc "...")`, `(@kind frames)`, `(@optional)`, `(@one_of ...)`, `(@at ...)`, `(@keyed)`. The lexer does not change (`@` is atom content today and appears in no bare atom in the 68 files), so the raw gate is untouched by construction; what changes is that metadata is metadata by spelling rather than by a closed seven-word trailing convention (tweak.cpp:18-22, D88, D218) that collides with `kind`, `desc`, `step`, `note` and `at` in real rows and real shapes. Lookup can then exclude it, so `get<std::array<float,3>>` of a ranged colour finally reads three numbers, and the shape grammar's own words stop reserving field names.

*Objection, and the proposer's answer:* Heritage: "DTA never marked anything; `@` is one more sigil every modder learns, and a reserved character is one fewer for names." Answer: `@` stays a symbol character everywhere (a symbol `a@b` is bare as before); only a tag that starts with `@` means anything, the same class of rule as `$x` and `#x` that DTA already has; the alternative keeps a seven-word list that real stacks trip on today and that D218 had to publish so tools could misread alike. Acton: "A per-child byte test in finish() on every parse, for a feature 99 rows use." Answer: it runs where the tag key is already computed, is held to D143's measured bar, and the intern-time bit variant costs nothing per parse if the first exceeds 1%; the win is on the lookup path too, where a multi-value read stops converting metadata it then rejects. D142's 'no new syntax or check' was about list operations; this reserves no bracket and no token.

**`signature-metadata`.** A definition's signature is one list and the body starts right after it: `{func NAME (PARAMS... META...) BODY...}` and, in a class or extend, `(NAME (PARAMS... META...) BODY...)` with the list mandatory. A parameter is `$x` or `($x TYPE)`, metadata is `(doc "...")` or `(status ...)` inside the list, told apart by node kind (Var, untagged array headed by a Var, tagged array), so no form is recognised by position and no body is swallowed (builtins.cpp:49-62, object.cpp:599-605). The types feed `check` and the reference, never the evaluator: a script call is checked like a native's, which is what D175/D213 let C++ describe and what this lets data describe.

*Objection, and the proposer's answer:* Acton and spec: "Static types creep in; the spec leaves out static typing and a compile step, and under lazy evaluation an argument's type is unknown until a native reads it." Answer: nothing is typed at run time; `check` already judges natives' literal arguments by declared types and skips commands and variables ('never pretend otherwise', spec section 5); typed script parameters are that same contract written in data, the one D213 accepted from a C++ description. Heritage: "DTA scripts never carried types or docs." Answer: `$x` stays legal and untyped, and the heritage fix here is the list itself: a definition read by node kind rather than by position, which is how every DTA form is meant to be read; the type is an option the list makes room for. Cost objection: a run-time match per argument is explicitly not built; if a host wants it, it is a measured flag later.

#### Angle: fewer concepts

FEWER CONCEPTS. Counted from what docs/language.md makes a newcomer learn before any semantics (merge by tag, keyed tables, lazy evaluation and dynamic scope are untouched by every proposal here), the text form has 29 spellings and placement rules: 7 lexical (two comment forms, Int with hex, Float, bare symbol, 'quoted symbol', "string" with two escapes); 4 brackets and sigils ((), {}, [] with its top-level ban, $); 10 directive spellings carrying 4 private placement rules (#define's same-line '(' at parse.cpp:881, [N ...] only at a file's top level at parse.cpp:540, #autorun's '{' at parse.cpp:902, (key #remove) in one slot per D143); 3 positional declarations ((pack ...) only as a first form, (origin "...") first-or-second with a String first per D91, a lone '#' a symbol but every '#x' reserved per D101); the seven-key trailing-metadata set (D88, tweak.cpp:18-43); the shape grammar's six reserved bare words (shape.cpp:16-18); {func}'s positional (status)/(doc); and booleans as 0/1 or a per-project TRUE macro. The five proposals take 29 to 13 by deleting mechanisms, not renaming them: one reader form #(tag ...) replaces every directive, macro spelling, declaration and marker (29 -> 17); one place sigil $name.path replaces the property bracket (-> 16); one annotation rule (@tag) replaces the metadata key set, the shape's reserved words and the positional definition grammar (-> 14); one interned text kind replaces Symbol, String and the quote rule (-> 13); and a top-level command simply runs, so no autorun door or table entry exists. They compose (the stacks' files read naturally under all five) and each is defensible alone; each is held to the survey's hard constraints: the tree keeps its ten kinds or loses one, Node stays 16 bytes and the Array header 24, no runtime work lands on a tweak read or a native call, round trip and one-token spans survive, and where a proposal drops the raw-DTA gate (D101) or a spec spelling it says so and gives the owner the decision. Two directions the angle names were considered and dropped. One bracket with a call sigil ((!f a) for {f a}, (.a b) for [a b]) teaches the same concept in a worse spelling and breaks the console's (ID {command}) line (console.cpp:56-95), the kit's '{' argv rule (commands.cpp:731) and the data-only policy's classification for nothing a designer can see; the two remaining bracket kinds after these proposals are the two distinctions the tree actually has (data, lazy code). A full Lisp (quote, let, lambda, lexical closures) abandons the no-special-forms evaluator and dynamic scoping the spec says to read twice (spec section 5; script.hpp:18-22; test_eval.cpp:88-102), cannot keep the 31 ns zero-allocation call, and is not a one-day prototype; the places proposal takes the one piece of that direction that fits (a path from a named root) and nothing else. Dropping quoted symbols alone, without merging the kinds, was also rejected: the round-trip constraint forces a spelling for every Symbol the tree can hold, so the quote can only go if the kind goes with it, which is the one-text proposal.

**`reader-forms`.** Everything the reader consumes and the tree never holds (twelve #name directives each with a private argument mini-grammar, two macro spellings, (pack ...), (origin "..."), #autorun, #remove) becomes one form: #(tag args...), a parenthesized form with # on its opening bracket, legal wherever a node may stand. The tag names the action from a closed table; the arguments are ordinary nodes, so a conditional's branches are balanced forms a tool can fold, a macro has one spelling and no same-line rule, a pack or origin is unambiguous anywhere, and a removal can stand beside its siblings. # is reserved only before a bracket, so #00aa00 and #1 are plain symbols, and [ is Property at every depth, so [1 0] at a file's top level is data. It is the right radical move because the four placement rules and the type-sniffing (D11, D82, D91, D143) are exactly where maps 0, 1 and 6 found the language misleading a newcomer, while the stacks and examples use none of the machinery those rules protect (0 macros, 0 conditionals, 1 #merge outside tests/corpus).

*Objection, and the proposer's answer:* DTA heritage, the strongest: Baker's one external measure of fidelity, 464 of 464 raw Harmonix files parsing (D101), goes to 0 of 464, and the owner chose that gate over two lenient rules; a Rock Band modder's #include, [TRUE 1] and #ifdef mean nothing to the new reader. Honest answer: the gate measured Harmonix's preprocessor, which Baker's own data never uses (map 5: 0 macros, 0 conditionals, 1 #merge outside tests/corpus); the stacks reach for layers and keyed tables instead. The conversion is mechanical and reversible for balanced conditionals, so the dump stays readable through the converter and the number stays a recorded result; what is given up is reading it natively, in exchange for retiring four placement rules the spec never asked for. This is the owner's decision (D101 was theirs), and the proposal asks for it rather than keeping two front ends, which the angle forbids. Acton's objection is smaller and measured, not assumed: a bracket-aware skip is one counter per bracket token where today's inactive region only lexes.

**`dollar-places`.** Script has two spellings for a place it reads or sets: $name, a variable cell, and [name] / [a b], a property of $this walked on into objects and tagged arrays, written with the bracket that also defines macros at the top level and that no top level may hold. Make $ the one place sigil: $name is a variable; $name.a.b is the path a.b read from what $name holds; [k] becomes $this.k, [a b] becomes $this.a.b, and [ ] leave the language (with reader-forms, entirely). A place may stand anywhere a Var may, a command's head included, and may start from any variable, not only $this. It is right because the Property kind's two documented meanings (the spec's 'property-path lookup', the docs' 'a property of $this, in a method') are one meaning with the root left implicit, and writing the root removes the handler-only restriction, the head refusal, the top-level ban and the bracket.

*Objection, and the proposer's answer:* Acton, the strongest: a Var read is one dereference by design (spec section 5, D44), and hiding a walk behind '$' blurs the one cheap thing in the evaluator. Honest answer: the walk exists today behind '[' and the split happens in the parser, not the evaluator: a $x without dots is exactly today's Var node and read; the dotted form is a Property node, as [a b] is, and costs what it cost, measured on the script rows before the trade is taken. DTA heritage: [...] is the talk's property-path spelling and raw DTA scripts use it; the converter rewrites [a b] to $this.a.b mechanically, and the raw gate is already a conversion under reader-forms. A smaller objection stands: $a.b reads to some as 'a variable named a.b', since symbols carry dots (duel.win_rate); no variable in the corpus has a dot, and the rule is one sentence in the Nodes table.

**`at-annotations`.** Values, metadata, shape words and a definition's doc are told apart today by five position-and-reserved-word rules: a tweak's value stops before a trailing array tagged from a closed seven-key set (D88, D218, tweak.cpp:18-43); a shape reserves at, keyed, optional, one_of, list and * (shape.cpp:16-18); a scenario and an objective reserve desc; {func} takes (status) and (doc) by position; (note) exists only on tweak rows. One rule replaces them: a tagged child whose tag begins with @ is an annotation. It is never a value, never a key, never a field; it trails the values, merges by tag like any child, and any reader asks for it by name. The bare words desc, kind, step, at and keyed go back to the data. It is right because the survey's single strongest corpus pinch (pain 1, shared by maps 3, 5 and 6: 19.5% of all atoms are metadata told apart only by order) is exactly this ambiguity, and because @ costs no lexer, printer or cache change: it is a symbol character already, absent from every bare atom in the repository.

*Objection, and the proposer's answer:* DTA heritage, the strongest: (width 2 (range 0 10) (step 1) (desc "Box width")) is the talk's own example (spec Appendix A) and the README's one-line promise, a sigil on every metadata key is noise on the line Baker exists for, and D88 settled this with a convention precisely to avoid new syntax. Honest answer: the promise is one line of C++ and one of data, and the data line gains one character per annotation; the talk's example never had to share a table with a (kind ...) field and Baker's corpus does at 27 sites; D88 plus D218 is a convention, a public helper and a seven-key list copied into two libraries, which is three things where one rule would do. Acton: a flag computed at parse for a convention only tools read; answer: it is set in the pass D143 already runs, read on no hot path (scalar reads untouched), and it retires a seven-compare loop the ImGui harness runs per tweak per frame; the prototype measures both.

**`one-text`.** Symbol and String are two node kinds with three spellings (bare, 'quoted', "string"), two escape sets, a rule that only Symbols key (D6), a printer case that cannot spell a symbol holding a quote (D13), and an error-path hint for the mistake the split invites. Baker already treats them as one at every seam: the JSON projection prints both as strings, (owners "td-encounter" td-combat) and a pack's version take either, one_of lists what desc describes. Make them one kind, Text: interned like a Symbol, written bare when is_bare_symbol allows and "..." otherwise with the two escapes, keying wherever it stands. The ' form leaves the language and a leading ' is a located error. It is right because the split is the concept a newcomer gets wrong first (a "bacon and eggs" key, for which D6's hint exists) and what it buys, text that dies with its load, is a memory class Baker's data has never needed: the whole corpus holds 348 strings, about 14 KB.

*Objection, and the proposer's answer:* Acton, the strongest: different data is a different problem. A name is compared by identity and lives forever; a text payload is read once and freed with its load. Interning every desc, path and song title forever spends the symbol table on data that never needs identity, cannot be reclaimed when a DLC is uninstalled, and taxes the parse of exactly the files (song lists, localization) where strings dominate; the spec kept Strings refcounted for this. Honest answer: that is the real cost and the proposal pays it knowingly. Baker's domain is tuning data and script (spec: not a serialization framework); its whole corpus interns about 14 KB; and no title has been asked to put a megabyte of localized text in a .dta file. Immortality is bounded by distinct texts, not by reads, and the parse cost is measured before the trade is taken: if the string-heavy benchmark loses more than 15%, the proposal fails on its own terms. DTA heritage: raw DTA keys by symbol and uses '...' widely; the converter rewrites both, and the raw gate is already a conversion under reader-forms.

**`top-level-runs`.** Data defines script through one door, #autorun {command}: a directive that takes exactly one brace form and hides a 31-line class behind a one-line spelling (Hearth's default.dta:78-108), while a file whose top level is commands (tests/corpus/scripts.dta, examples/scripting/rules.dta, examples/calculator/functions.dta) is already how hosts write script, run by hand with ctx.run over the tree. Delete the door: a command at a file's top level is a thing to run, collected into the session's autorun list in read order and kept out of the tree, exactly as #autorun collects it today; a command inside an array stays a value. A newcomer learns nothing: what looks like a call at the top of a file is one. It is right because the tree is for lookup and a top-level command has no path to be found by; it is an untagged value of the root, which an Overwrite merge of a higher layer's top-level values would replace wholesale, so 'run me' is the only coherent meaning a top-level brace can have.

*Objection, and the proposer's answer:* DTA heritage, the strongest: #autorun is the original's spelling (D11), and the talk's split is clean: the tree is data and directives act; a top-level brace that vanishes from the tree makes read_file return less than the file holds, and the repro-script pattern (cookbook) and the corpus test both read commands back out of the tree today. Honest answer: the split stays (the tree is still data, and top-level braces never appear in it, as #autorun's commands do not today); what changes is that the file says 'run' by position instead of by a word, and the two patterns that ran top-level commands from the tree move one call to session.autorun(), which is where a Config always looked (D107). The Acton objection is nil: nothing moves at runtime. The honest residue: a tool that printed a tree to reproduce a file loses the commands unless it prints the session's list first, which to_dta already loses for #autorun today; and read_file's session-less overload cannot return them, so the repro pattern must hold a LoadSession.

### Not prototyped, and why

- **column-tables / columns-tables (#columns header with positional cells).** Both page-angle and machines-angle variants fell to the people judge's fatal: a symbol-list cell such as `(jab low_kick)` or `(-> wheat)` is lexically a tagged array and ends the cells, so the headline frame-data and economy tables parse to the wrong tree silently, and fewer cells than columns shifts every later cell with no error. The fix is clear and both judges stated it (exactly N cells per row with `_` holes; any parenthesized array in cell position is a cell whatever its first node), the cost judge ranked it fourth and the tools judge sixth, and it loses the seventh slot only to rule 5's requirement for two cost-low briefs; it is the first follow-up, with the fix as its grammar.
- **expr-precedence.** The superset of curly-infix: a Pratt grammar of about 230 of the 310 free lines whose output the text never spelled, a printer lossy by construction, a precedence table every external tool must re-encode (D220's pain), and precedence as a new silent-failure class in a language that forbids special forms; the proposer itself recommended building it only on evidence from curly-infix's rewritten corpus, and the one mixed case the corpus has (comparisons under and/or) is a two-tier design question in the curly-infix brief.
- **margin-bars.** The cost judge's fatal: zero information gain. The tree is byte-identical to today's, so `(ball | kind ball | pos ...)` is still misread by split_metadata, while a bare `|` is reserved (present in the external corpus per D101) and the grammar gains its first in-bracket layout rule. Its column view survives as the at-metadata brief's optional printer alignment.
- **literal-forms (units, colors, hex width, booleans).** The tools judge's fatal: silent re-typing of today's symbol-fallback atoms (`12abc`, pinned in odd_tokens.dta, becomes Int 12 with a unit; bare `true`/`false` change type) is the reinterpretation-without-error D101 refused; six of Node's seven reserved bytes, a per-file unit table in the cache (kVersion 7), three TextTokenKinds and about 250 lines for a check-time claim the engine never uses, and `15%` reading as 15. Units belong in a shape `(@kind)` check on the at-metadata base; its booleans-and-hex half is true-false-hex.
- **true-false-hex.** Consensus-positive (people 4, cost 3, tools 4) and no fatal, but small: one Node spelling byte and a kVersion bump for about 12 bool rows and 3 hex rows in the corpus. The seven slots went to larger ideas; it is the obvious eighth, half a day, and the at-metadata and hash-declarations briefs are told not to spend the Node byte meanwhile.
- **typed-rows.** The cost judge's fatal: over budget together with its prerequisite at-attributes (about 290 lines against 310), tool-only facts stored as runtime nodes in the merged tree (`(@type T)` per typed row), and a `(`-tag whose text and Symbol differ so every text tool must learn the `:` split. The declaration (hash-declarations' `#shape`, at the table) is where a type belongs; the `lo..hi` literal is a question in the at-metadata brief.
- **tables-declare-rows.** The people judge's fatal: as the stacks are written, packs are spliced by #require, so the pack's row-less mirror `(fighters (@each fighter ...))` and the data's `(fighters (kestrel ...))` are two root arrays with one tag in one layer, repeated tags do not fold within a layer (D31), lookup takes the first, and every lookup under the table fails. It also stands on at-attributes and typed-rows (twice the headroom). Its 'declare the shape where the rows are' is hash-declarations' at-the-table `#shape`, which is a session record and cannot shadow a table.
- **at-refs (value references resolved at merge).** Scored 3 by all three judges but with gaps each named: the tools judge found Config::set edits scratch in place without a merge, so tuning a reference's target live leaves every referrer stale, and a file read alone holds symbols until resolve_refs; the cost judge noted it keeps macros, so Baker would carry two value-indirection mechanisms while no stack uses either; the people judge that `@` would carry a second meaning. With `@` taken by metadata and the row sigil decided, a reference sigil is a decision for the next round.
- **proto-records.** The tools judge's fatal: shape::validator reads each layer's own tree where a prototype is an unresolved symbol the proposal says to skip, so `(bot @shapes.cpu_level ...)` declares bot with no fields and bots is governed by nothing, silently, the D108 failure it cites as motivation. The cost judge: budget-sized machinery for two duplicated shape declarations; the people judge: a record that inherits is not whole on the page. Name reuse belongs with declarations.
- **key-refs (`&path` checked names).** The tools judge ranked it first and the people judge last: `(lay &pieces.straight_40 &pieces.kicker_15 ...)` puts a sigil and a table name on every one of fifteen names where a shape field `(lay (list (ref pieces)))` says it once in the pack with no noise in the data; the relative `&.` rule is a scope to learn; the proposer expected to lose to the shape route. A `(ref PATH)` field type is a follow-up to hash-declarations' `#shape`.
- **patch-rows (@key, no fold).** Merged into path-rows; its fatal (two rows under one prefix leave two root arrays, so diff and layer_effect under-report the agent's own changes) is resolved there by the fold.
- **path-rows (page: #paths), path-rows (keys: @key), path-rows (machines: dotted tag).** Merged into the path-rows brief: the per-file mode and its dependence on indent-lines are dropped, the later-wins duplicate rule is replaced by a located error, and the dotted-tag trigger's silent class is kept behind a switch for the gate count only.
- **at-attributes, at-annotations.** Merged into at-metadata: their trailing rule refuses their own shape and record examples (people judge) and makes write_back_to's insertion unparseable (tools judge); at-attributes' intern-time bit and header count and at-annotations' reach into {func}'s status/doc are taken.
- **one-macro-one-hash.** Merged into hash-declarations: the `#`-before-a-letter rule and `#define` as a flag only are taken; the `''` doubling (people: rare, and it changes `'a''b'`'s meaning) and overflow-as-symbol (cost: the lenient rule D101 refused) are dropped.
- **reader-forms (#(tag ...) for every directive).** The radical superset of hash-declarations: it drops the native raw gate to 0 of 464, converts about 190 test strings and 24 doc blocks, turns `#else` into a second complementary form a renamed flag must track twice (the people judge's trap), and makes `#(` an Open token carrying TextTokenKind::Directive (the tools judge's editor ambiguity). Its folding conditional is a design question in hash-declarations.
- **declare-directives.** Merged as the center of hash-declarations, with the tools judge's check warnings and LayerPolicy rule added.
- **pinned-patches.** Merged into layer-markers as `#was` and the note preamble, confined to layer-tree readers through one helper; the cost judge's hot-reader worry and the tools judge's missed-reader worry are answered there.
- **doc-comments.** Two fatals: the cost judge's (a `;; ` banner, the commonest banner spelling in Lisp-style and DTA files, silently becomes the desc of the next array) and the tools judge's (a trailing `;;` attaches to whatever `)` closed last, so on Hearth's and Duel's continued rows a comment lands inside an untagged tuple and changes what the game reads). The note half everyone wants is delivered by layer-markers' `(note ...)` preamble and at-metadata's `(@note ...)` on any row; comments stay trivia, with read_structure's TextComment.kind as the tool-side option.
- **one-form.** Merged into indent-lines only as the printer's house-style defaults (indent 3, width 100), which closes the inserted-block mismatch; the 220-line formatter that owns every non-meaning byte is a tool for later, outside the core beside shape (the cost judge's improve), and its run-alignment rules would widen promote --patch diffs (tools judge).
- **one-text (Symbol and String as one interned kind).** The cost judge's 1: payload text is not a name; interning every string forever taxes parse by the proposal's own +10 to +30% on string-heavy files, grows a table no layer removal reclaims, bumps the cache and changes D222's digest for every tree holding a string (a lockstep major), for a key spelling the error hints already compensate for.
- **top-level-runs.** The cost judge ranked it second but the tools judge found it fatal as written: Context::eval(text) (context.cpp:471-476), the console's non-request path, eval_request's fallback and 172 test sites call ctx.eval("{...}") and run the tree's nodes, so a top-level brace collected into the session would run nothing, silently. The fix exists (eval runs session.autorun()), it is -15 lines and a half day, but it is a door's removal, not a radical syntax; hash-declarations keeps `#autorun`.
- **signature-metadata.** Scored 3/4/4 with no fatal, script-only, 7 funcs and 2 classes; held for the next round because the typed-parameter spelling (`(($x float))` versus `$x:float`) depends on whether `:` gets a meaning, which this round's briefs do not decide.
- **self-dot-methods + dollar-places.** Scored 3 by every judge; the two contradict each other on `$a.b` (a method send versus a property path), both canonicalize to `{$this m ...}`, and the payoff is 34 sites in one Hearth class and 2 corpus lines; dollar-places standalone also removes `[NAME ...]` macro definitions unless a macro proposal lands first (tools judge). The Property-headed command and the class-body checker are good follow-ups to curly-infix.
- **str-interpolation.** No consumer (0 of the corpus's 8 say/print sites put a value in a string), a string built from the Context's allocator during a call, a third escape in a two-escape language, holes that cannot hold a quote; the proposer ranked it last. `str` as a 25-line builtin is the half worth having.
